# 드림지키미 자체 엔진

대화창과 실제 모델이 바뀌어도 같은 작업의 목표와 정정을 이어받도록 만드는 첫 구현입니다. 모델이 답변을 만든 상태와 그 답변을 실제 결과로 사용할 수 있는 상태를 구별합니다.

## 저장하고 이어받는 내용

SQLite는 파일 하나에 자료를 보존하는 데이터베이스입니다. 사용자, 논리적 아이디와 작업 번호를 함께 구별하여 목표, 우선순위, 정정 규칙과 미완료 의무를 저장합니다. 프로그램을 다시 시작할 때 같은 파일과 아이디로 기록을 읽습니다. 모델의 비공개 기억이 저절로 유지된다고 가정하지 않습니다.

실제 모델, 대화 연결 및 실행 차수는 논리적 아이디와 별도로 저장합니다. 담당을 교체하면 새 실행에 같은 작업을 연결하고 이전 실행이 늦게 낸 답변을 현재 결과로 반영하지 못하게 합니다.

## 모델에 허용하는 기능

모델은 현재 작업의 기록을 읽고 후보를 제출합니다. 사용자 권한으로 목표를 바꾸거나, 검사가 통과했다고 승인하거나, 미완료 의무를 지우는 기능은 모델용 연결에 제공하지 않습니다.

사용자 지시의 신원 확인과 위임 판단은 이 엔진을 호출하는 프로그램의 책임입니다. Python 함수에 검토 완료 값을 전달하는 것 자체가 실제 사람의 승인이나 의미 검사를 수행해 주지는 않습니다. 이 첫 구현을 인증된 웹 서비스로 연결하는 작업은 별도로 남아 있습니다.

## 실제 사용 전에 확인하는 내용

후보에는 원문, 내용 식별값, 사용 목적과 실제 사용한 자료 항목을 연결합니다. 검사 결과는 당시 목표 변경본, 실행 차수, 자료 변경본과 후보에 묶입니다. 최종 소비 때 이 값들을 한 번의 데이터베이스 처리 안에서 다시 확인합니다.

자료를 정정하면 실제로 그 항목을 사용한 후보를 다시 검사합니다. 사용 기록이 완결되고 정정 항목을 사용하지 않은 후보는 유지할 수 있습니다. 사용 기록이 불명확한 상태를 무관함으로 바꾸지 않습니다. 이것은 자료와 결과의 사용 관리이며 학습된 가중치의 영향을 자동으로 제거하는 기능은 아닙니다.

모델에 실제 전달한 자료 항목과 변경 번호는 엔진이 기록하고 후보에 자동으로 연결합니다. 모델이 인용을 생략해도 전달 사실은 없어지지 않습니다. 다른 경로로 제공한 입력까지 기록이 완결되는지는 호스트가 확인해야 합니다. SDK의 `source_selection`은 호스트가 정하며, 생략하면 해당 작업에 등록한 전체 자료가 전달 대상입니다. 따라서 호스트는 그 모델에 제공해도 되는 자료만 작업에 등록해야 합니다.

최종 사용에는 현재 미완료 의무마다 호스트의 확인 기록이 필요합니다. 엔진은 확인할 의무가 빠졌거나 바뀌면 이전 승인을 거부합니다. 의무가 의미상 실제로 이행됐는지는 호스트가 판단합니다. 생성·정정 전후의 목표와 자료 원문은 변경 이력에서 회수할 수 있습니다. 전체 대화에서 생각의 관계를 자동 추출하고 필요한 맥락을 자동 선정하는 기능은 이번 구현에 포함하지 않습니다.

## 오류와 창의적 후보

관련 사용을 격리하거나 실행을 중단해도 후보 원문은 남깁니다. 다른 목적의 창의적 후보로 보존하는 것과 사실로 승인하는 것을 구별합니다. 다시 배정하려면 현재 조건의 재검사가 필요하며, 기다렸다는 이유만으로 자격을 회복하지 않습니다.

텍스트가 사실인지, 사용자의 자연어 목표를 완전히 지켰는지 자동으로 증명하는 프로그램은 아닙니다. 이 구현은 확인된 검사 결과를 현재 작업과 연결하고 확인되지 않은 후보가 최종 결과가 되는 것을 제한합니다.

재개 때에는 맥락 복구, 정정 재검사, 사용 범위, 미완료 의무 보존을 모두 확인해야 합니다. 외부 서비스에서 이미 일어난 행위를 데이터베이스가 되돌려 주지는 않습니다. 외부 실행 중복 방지와 실제 처리 결과의 확인은 연결 프로그램이 담당합니다.

재개 전 `snapshot()`으로 실제 상태를 검사한 다음 그 결과의 `review_state_hash`를 `resume_after_check()`에 반드시 전달합니다. 검사 뒤 목표·의무·실행 차수·자료가 바뀌면 이전 검사로 재개할 수 없으며 다시 검사해야 합니다. 이 해시는 검사 대상의 동일성을 대조하며, 실제 사람이 검토했다는 사실 자체를 증명하지 않습니다.

## SDK 연결과 논술 적용

SDK는 모델 실행에 도구를 연결하는 개발 도구입니다. `dreamkeeper_claude_sdk.py`는 자체 엔진의 맥락 읽기와 후보 제출 기능을 SDK 내부 도구로 싣습니다. 모델의 원시 응답과 승인 후의 결과를 구별합니다. 별도 모델 여럿을 필수로 하지 않습니다.

`dreamkeeper_essay.py`는 교사 제공 기준표와 실제 답안의 원문 위치를 연결해 점수 제안을 검사합니다. 대학별 공식 기준표를 임의로 만들어 넣지 않습니다. 실제 논증의 타당성과 학생 교육효과는 별도 검토 대상입니다.

`dreamkeeper_training.py`와 `train_dreamkeeper.py`는 허용 자료의 학습 준비 및 수정 가능한 모델의 실제 학습 경로를 구별합니다. SDK 연결만으로 외부 상용 모델의 가중치를 바꾸지는 않습니다. 전체 또는 추가 가중치 학습을 선택할 수 있고 특정 학습 방식이 특허의 전부라는 뜻은 아닙니다.

## 적용 범위

기존 운영 경로와 외부 모델 목록은 변경하지 않습니다. 이 코드는 별도 검토 브랜치에 추가하며 운영 서비스에 자동 연결하지 않습니다. 실제 외부 모델 응답, 대규모 학습 효과와 운영 성능을 확인했다는 주장은 포함하지 않습니다.

## 가상 자료로 바로 실행

프로젝트 폴더에서 `python scripts/demo_dreamkeeper.py`를 실행하면 실제 SQLite 파일로 저장·재시작·담당 교체·자료 항목별 정정을 확인합니다. 자료와 검토 기록은 모두 가상 예시이며 모델 호출과 학습을 하지 않습니다. `True`라는 검사 값을 실제 검토 없이 복사해 쓰면 안 됩니다.

전체 신규 시험은 `python -m unittest discover -s tests -p 'test_dreamkeeper*.py' -v`로 실행합니다. SDK와 학습 라이브러리가 없어도 이 시험은 실행되며, 해당 외부 연결은 가상 라이브러리로 검증합니다. 이는 실제 LLM의 성능 시험과 구별됩니다.
