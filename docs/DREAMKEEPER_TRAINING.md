# 드림지키미 가중치 학습 준비

이 코드는 현재 목표를 따르는 사례, 오류를 분류한 사례 및 다른 목적에서 검사한 대안을 학습 자료로 준비합니다. 전체 가중치와 별도 추가 가중치를 선택할 수 있습니다. `scripts/train_dreamkeeper.py`는 그중 지도학습을 구현한 한 예이며, 특허의 학습 범위를 지도학습이나 파인튜닝으로 한정하지 않습니다. 추가 가중치 예에는 LoRA를 사용하지만 전체 가중치 방식에는 LoRA가 필요하지 않습니다.

기존 `training/rl/contract.py`의 `TUTOR_POLICY`는 교사의 다음 질문 선택을 위한 별도 계약입니다. 새 모듈은 이를 범용 모델 학습 허가로 바꾸지 않습니다. 학생 자료가 포함되면 기존의 동의·가명 처리와 `CLEARED_FOR_TUTOR_MODEL_TRAINING` 검토도 계속 필요합니다.

## 실제로 동작하는 부분

`app.services.dreamkeeper_training.load_bundle`은 다음을 검사합니다.

- 자료 파일은 한 번 읽은 동일 바이트의 해시를 확인하고 그 바이트만 사례로 해석합니다. 읽은 뒤 파일이 교체되어도 다른 내용을 학습행으로 섞지 않습니다. 해시는 내용을 구별하는 계산값이며, 사람의 신원이나 법적 권리를 증명하는 서명은 아닙니다.
- 원래 목표와 정정의 변경 번호, 실제 소비한 출처의 항목·변경본·자료 계열, 현재의 학습 권한 및 철회를 대조합니다.
- 확인되지 않은 오류나 미검사 후보를 정답 또는 실패 표본으로 사용하지 않습니다.
- 같은 사건·출처 계열과 같은 입력이 학습용과 최종 평가용에 걸쳐 사용되지 않는지 확인합니다.
- 외부 API 출력, 앱 대화 출력과 출처 미상 자료를 새 학습 자료로 승인하지 않습니다. 출처 계열과 실제 소비 항목의 완결성은 신뢰된 호스트의 기록이 전제입니다. 모델이 스스로 `True`라고 말한 것으로 완결성을 증명하지 않습니다.

`write_draft_bundle`은 자료와 검토 전 목록을 작성합니다. 상태는 항상 `PENDING_REVIEW`이며 학습 허가를 자동으로 만들지 않습니다. 별도 검토자가 실제 파일 해시, 권리와 동의 근거, 허용 목적 및 현재 권한을 확인하여 검토 기록을 제공해야 합니다. 모델에 이 검토 기록을 수정할 도구를 제공해서는 안 됩니다.

## 입력 파일

실제 학습에는 다음 파일이 필요합니다. 학생 자료나 실제 사용자 대화를 이 문서의 시험 자료처럼 임의 승인하면 안 됩니다.

| 파일 | 담는 내용 |
| --- | --- |
| records.jsonl | 사례별 원래 맥락 입력, 검증된 목표 응답, 논리적 아이디·작업·변경 번호, 판정과 검토, 실제 소비 출처 항목, 자료 계열과 학습·평가 구분 |
| manifest.json | 자료 전체의 검토 상태와 해시, 허용 학습 목적, 현재 권한 변경 번호 및 검토 번호 |
| current.json | 현재 목표·정정 변경 번호, 출처 항목별 현재 변경본·권리 검토·허용 목적, 모델 변경본별 현재 학습 허가·권리 검토·파일 해시, 철회 목록 |
| recipe.json | 이전 모델 변경본과 권리 검토, 모든 로컬 모델·토크나이저 파일의 해시, 전체 또는 추가 가중치 방식, 학습 설정 |

정확한 필드와 가상 예는 `tests/test_dreamkeeper_training.py`에 있습니다. 시험의 `synthetic-*` 표시는 테스트 전용이며 실제 권리 검토가 완료됐다는 의미가 아닙니다. `prompt`에는 필요한 현재 맥락을 넣고 `target`에는 확인된 바른 판단을 넣습니다. 원래의 오류를 그대로 사실 정답으로 복사하지 않습니다. `VERIFIED_ALTERNATIVE`는 별도 목적에서 확인된 대안이며 원래 목적의 정답 자격을 만들지 않습니다.

## 실행 방법

프로젝트 폴더에서 다음 명령을 실행하십시오. 모델 경로는 이미 확보하고 검토한 로컬 파일 폴더여야 합니다.

```bash
python scripts/train_dreamkeeper.py --dataset /data/records.jsonl --manifest /data/manifest.json --current-state /data/current.json --recipe /data/recipe.json --model-path /models/reviewed-model --check-only
```

`--train`을 쓰지 않으면 기본적으로 자료·권한·로컬 파일 해시만 확인하며 PyTorch, Transformers 및 PEFT를 불러오지 않습니다. 이것은 실제 모델 적합성이나 성능 검증을 마쳤다는 뜻이 아닙니다.

명시적으로 실제 학습을 실행할 때에는 장치에 맞는 PyTorch와 저장소의 학습용 의존성을 별도 설치한 뒤 다음과 같이 실행하십시오. 운영 앱 안에서 실행하지 마십시오.

```bash
python scripts/train_dreamkeeper.py --dataset /data/records.jsonl --manifest /data/manifest.json --current-state /data/current.json --recipe /data/recipe.json --model-path /models/reviewed-model --output-dir /training/new-model --train
```

이 실행기는 모델을 다운로드하거나 원격 모델 코드를 실행하거나 공개 저장소에 결과를 올리지 않습니다. 검토한 로컬 안전 가중치 파일을 사용합니다. 대상 토크나이저에 대화 형식이 있어야 하고, 입력 맥락과 목표 응답의 경계를 정확히 확인할 수 있어야 합니다. 길이를 넘는 사례를 조용히 잘라내지 않습니다. 완전한 반복 학습을 한 번 이상 수행하는 단일 학습 프로세스를 지원합니다. 분산 학습이나 다른 추가 가중치 방식은 후속 구현 대상입니다.

실제 학습에서는 입력 문맥에 대한 정답 모방을 하지 않도록 사용자 입력 토큰의 손실을 제외하고, 검증된 목표 응답 부분으로 수치를 조정합니다. 학습 설정은 최초에 읽은 바이트에서 해석하고 그 바이트의 해시를 고정하므로, 모델을 불러오는 동안 설정이 바뀌면 학습 전에 거부합니다. 로컬 모델 파일 해시는 모델을 읽기 전과 읽은 뒤 및 결과 저장 전에 다시 확인합니다. 매 학습 단계에는 현재 모델 학습 허가와 자료 권한·철회 및 검토 설정의 변경을 다시 확인합니다. 이 검사는 신뢰된 호스트가 모델 입력 파일과 권한 기록을 관리한다는 전제로 수행하며, 악의적인 동시 모델 파일 교체까지 완전히 증명하는 운영 인증 절차는 아닙니다. 확인이 실패하면 완료 영수증을 만들지 않습니다.

## 가중치 변경과 활성화를 구별

학습 후 각 학습 가능 가중치의 실제 바이트를 이전 값과 비교합니다. 파일을 저장했어도 실제 변화가 없으면 성공으로 보고하지 않습니다. 기록에는 이전·이후 해시, 바뀐 가중치 이름, 실제 소비 자료 항목과 설정 및 평가용 손실이 들어갑니다. 평가용 손실은 목표 유지·사실 정확성·창의성의 전체 행동 평가를 대신하지 않습니다.

출력은 항상 `PENDING_BEHAVIORAL_REVIEW`입니다. 모델 파일 작성이나 숫자 변화만으로 서비스에 반영하지 않습니다. 학습 후에도 엔진의 현재 목표·정정·권한·예상 활성 모델 검사와 별도의 행동 평가를 통과해야 합니다. 자료 삭제가 이미 학습한 영향까지 지웠다는 의미도 아닙니다.

이번 구현 검증에서는 실제 대형 모델·GPU 학습을 실행하지 않았습니다. 표준 라이브러리 검사와 가상 가중치의 실제 바이트 비교를 시험했습니다. 테스트 성공을 LLM의 맥락 망각이나 환각 감소 실측으로 표현하면 안 됩니다.
