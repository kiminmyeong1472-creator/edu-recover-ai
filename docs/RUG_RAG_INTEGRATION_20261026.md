# RuG 전성분 대조와 공식 근거 검색

RuG는 제품명과 성분 분석이 끝난 전성분 목록을 받아 등록한 알레르겐을 규칙으로 대조한다. 검색 증강 방식(RAG)은 공식 자료를 먼저 찾아 원문을 표시하는 데만 사용한다. 성분 포함 여부를 언어모델에 맡기지 않는다.

## 입력과 결과

- `/life`의 RuG 메뉴에서 `/life/rug`로 이동한다. 생활앱 계정으로 로그인해야 한다.
- 제품명과 전성분을 붙여 넣거나 성분 한 열의 텍스트·CSV 파일을 선택한다. 파일은 브라우저에서 읽어 같은 서버에 문자로 제출한다. 이미지 입력과 문자 인식 기능은 없다.
- 입력 원문과 이름을 정리한 결과를 함께 확인한다. 잘못 나뉜 성분은 한 줄에 하나씩 수정할 수 있다. 숫자 사이 쉼표가 있는 `1,2-Hexanediol`은 하나의 성분으로 유지한다.
- 고객이 등록한 성분 이름을 그대로 결과에 표시한다. 일부 성분만 확인한 경우에도 확인된 일치는 숨기지 않는다.
- 전성분이 일부이거나 향료처럼 여러 성분을 묶은 표기가 있으면 최종 판정을 보류한다. 확인한 성분 수를 넣은 지정 문구를 결과 바로 아래에 표시한다.
- 같은 제품명과 확인된 판매 주소로 다시 입력하면 해당 계정의 이전 결과를 찾아 추가·삭제 성분과 일치 결과의 차이를 표시한다. 고객 원문·수정 성분·등록 알레르겐·이력은 기존 AES-256-GCM 암호화 저장소에만 기록한다.
- 올리브영 판매 확인 자료가 없으면 확인된 범위의 대조 결과만 표시하고 최종 판정을 보류한다. 상품 주소만으로 판매 확인이 끝났다고 처리하지 않는다.

## 공식 근거와 답변

허용 출처는 식약처, 대한화장품협회 성분사전, EU CosIng, EU SCCS 의견서, 미국 FDA다. 검색으로 찾은 원문 문장에 출처명·문서 제목·확인일·원문 주소를 붙인다. 문장과 문서의 체크섬(SHA-256, 내용이 바뀌었는지 대조하는 값)을 다시 확인한다. 원문 문장을 찾지 못하면 `NO_EVIDENCE`와 지정한 근거 없음 문구를 반환한다.

기본 검색은 낱말의 빈도와 문서 길이로 순서를 정하는 BM25다. 별도 설치한 로컬 공개 임베딩 모델(글을 숫자 묶음으로 바꾸는 모델)이 있으면 의미 검색 결과와 BM25 순위를 RRF 방식으로 합친다. 임베딩은 SQLite에 저장한다. 모델이 없거나 실패하면 BM25만 사용하고 실제 검색 방식을 응답에 표시한다. 서버 요청 중에는 모델이나 공식 원문을 내려받지 않는다. Claude·OpenAI 연결은 추가하지 않는다.

임베딩은 `requirements-rug-embeddings.txt`와 로컬 모델을 별도로 준비한 뒤 `RUG_EMBEDDING_MODEL_PATH`에 해당 폴더를 지정한다. 원격 코드 실행과 자동 다운로드를 허용하지 않는다. 원문을 다시 동기화하면 모델이 준비된 경우 문서 조각의 임베딩도 저장한다. 실제 공개 모델을 설치하지 않은 이번 로컬 검증에서는 BM25가 사용됐다. 결합 순위 계산은 시험용 숫자 벡터로 별도로 검사했다.

원문 일치는 문장이 원문에 있다는 검사다. 원문의 사실성이나 모든 문장 사이의 모순을 자동으로 판별했다는 뜻은 아니다. 근거 화면은 여러 출처를 함께 표시하고 최종 판단을 보류한다. 이 동작이 성분 규칙 대조 결과를 바꾸지는 않는다.

## 운영자가 실행할 명령

저장소 루트에서 실행한다. 출처 사이트에서 원문을 실제로 읽는 명령과 이미 저장한 자료를 검사하는 명령은 구별한다.

```sh
python scripts/rug_rag_sync.py --sync-all
python scripts/rug_rag_sync.py --status
python scripts/rug_acceptance.py
python scripts/rug_import.py --products 검증된_실제제품.json
```

`--database`를 지정하면 별도의 로컬 검사 DB를 사용할 수 있다. `--seed-index`는 출처 개요만 등록하며, 개요는 원문 답변이나 원문 확보 건수로 사용하지 않는다. 제품 예시를 실제 자료로 반입하지 않는다. 검증된 제품 자료가 없으면 반입 0건으로 기록한다.

출처 동기화는 출처마다 지정된 기본 페이지 한 건을 읽는다. 사이트 전체나 모든 성분·의견서·고시 첨부파일을 수집하는 명령은 아니다. 특정 고시나 개별 성분에 답할 근거가 없다면 답변을 보류한다. 추가 원문은 공식 주소·확인일을 갖춘 검수 자료를 `--manifest`로 별도 반입한다.

## 저장 위치와 검증 범위

기존 저장 위치 설정이 있으면 그 위치를 사용하고, 없으면 `RAILWAY_VOLUME_MOUNT_PATH`를 사용한다. Railway 볼륨이 지정됐는데 기존 저장 위치가 볼륨 밖이면 RuG는 기록을 거부한다. 공개 원문 색인과 고객별 암호화 DB를 구분한다.

2026년 10월 26일 로컬 동기화에서 MFDS 1건 9조각, KCIA 1건 2조각, COSING 1건 6조각, SCCS 1건 16조각, FDA 1건 28조각을 확보했다. 실제 제품 반입은 0건이었다. 이는 운영 서버의 문서 수나 배포 완료를 뜻하지 않는다. 운영 반영 후 다시 동기화하고 상태 응답과 재배포 전후 문서 수를 확인해야 한다.

`tests/test_rug_integration.py`는 전성분 입력, 일치·미일치·보류, 동의어 충돌, 재검토, 원문 대조, 암호화, 계정 분리, 지속 저장 위치, 브라우저 화면을 검사한다. 해당 파일의 가상 제품과 가상 문장은 시험 자료이며 실제 제품이나 공식 원문으로 반입하지 않는다. `tests/fixtures/rug_official_questions.json`과 `scripts/rug_acceptance.py`는 실제 색인에서 정답 근거 질문 10개와 근거 없는 질문 10개를 재검사한다.

## 반영 절차

작업 브랜치는 `codex/rug-rag-integration-20261026`이다. 정식 코드에 합치도록 요청하는 검토 절차(PR), 자동 검사(CI), 대표 승인, main 병합, Railway 배포, 운영 동작 확인은 별도 단계다. 대표 승인 전 main에 병합하지 않는다. 이번 변경에는 별도 설치기와 사진·화면 전송 코드가 들어가지 않는다.
