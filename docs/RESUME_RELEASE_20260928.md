## 1. 변경 요약

### 1.1 인증·AI 공급자 호출

- 서버 API 키를 사용하는 출제·검증 채널에 관리자 인증을 적용했다. 쿠키 인증 요청에는 기존 동일 출처 검증이 적용된다.
- OpenAI 인증 실패 시 Gemini로 자동 전환하던 경로를 제거했다. 실패 후 OpenAI 재시도를 계속 막던 임시 런타임 hold도 제거했다.
- 실행 요청마다 공급자를 명시한다. 실패하면 선택한 공급자의 실패를 반환하며 다른 공급자를 호출하지 않는다.
- OpenAI 인증 오류와 Gemini 할당량·호출 제한 등을 구분하여 안내한다. 공급자 오류 본문, API 키, 원문 자료를 진단 로그에 복사하지 않는다.
- ZDR 및 에이전트 허용 설정의 잘못된 값이 기본 차단 정책을 해제하지 않게 했다. 실제 ZDR 계약·승인을 새로 확인하거나 환경변수로 승인하지 않았다.
- API 준비 상태는 설정 확인 결과이다. 실제 인증·과금·생성 성공을 보증하지 않는다.
- 개별 교사 계정·기관 권한·과금 체계가 없는 현재 범위에서 공개 교사 화면은 편집·초안 출력을 제공하고, 서버 키를 사용하는 AI 작업에는 관리자 로그인이 필요하다.

### 1.2 출제·독립 검증·출처 증명

- 한 AI의 출제가 끝나면 다른 AI 한 개로 전체 문항을 검증할지 선택한다. 출제 AI는 후보에서 제외한다. 아니오를 선택하면 문항 작업실에 초안을 유지한다.
- 공급자 선택 없이 복수 AI를 호출하던 `/verify-problem` 경로는 사용 중단 안내를 반환한다. UI는 명시적 공급자 검증 채널을 사용한다.
- 원출제 공급자, 실행 ID, 전체 문항 해시를 서명된 `origin_proof`에 결속했다. 공급자·실행 ID·문항·증명이 일치하지 않으면 외부 검증 호출 전에 차단한다.
- 교사 편집은 인증된 `/owner/authoring/revise`에서 새 문항 해시에 재결속한다. 최초 출제 공급자는 유지한다.
- 독립 검증 PASS에만 별도 목적의 `verification_proof`를 발급한다. 출제 증명을 검증 PASS 증명으로 대용할 수 없다.
- 문항 수정 시 이전 검증 결과와 교사 승인을 무효화한다. 검증 도중 문항이 바뀌면 늦게 도착한 PASS를 현재 문항에 적용하지 않는다.
- 모순된 PASS 응답, 잘못된 JSON, 검증 미완료 상태는 통과로 처리하지 않는다.
- 현재 증명은 원문이나 키를 담지 않으며 관리자 세션 서명키와 분리된 용도로 서명한다. 유효기간은 7일이며 서버 재시작·관리자 자격정보 변경 시 무효화된다. 과거 브라우저 작업공간에 증명이 없으면 독립 검증을 완료한 것으로 인정하지 않는다.

### 1.3 구조화 AI 교수자료·교사용 전자칠판

- 중심을 전체 학습지도, 기초 설명·시범, 성립조건, 추론 연결, 심화 적용과 별도 독립 평가로 구성했다. 산파식 질문은 선택사항이다.
- 조건 시나리오별 버전과 논리 연결에 설명 장면·음성 원고·문항·정답을 결속한다.
- 초안 변경 시 기존 공개를 철회하고, 자료·조건 버전 및 검토 상태가 맞지 않으면 학생·전자칠판 제공을 막는다. 구조 검사와 교사의 의미·정답 검토는 별개이다.
- 일반 수업도 교사 검토와 명시적 확정 후 학생에게 제공한다. 학생에게는 현재 단계만 제공하며, 중지된 수업이나 아직 제공되지 않은 단계에 대한 응답을 막는다.
- AI 출제 자료의 수업 연결은 서명된 원출제·독립 검증 기록과 실제 문항을 대조한다. 클라이언트의 PASS 문자열만으로 공개하지 않는다.
- 답을 보여준 연습, 같은 문항 재응답, 지원을 사용한 수행을 독립 전이 증거로 취급하지 않는다.
- 응답 당시 자료 스냅샷을 보존하여 이후 자료 편집으로 과거 응답의 채점 근거가 바뀌지 않도록 했다.
- DOCX 출력은 모든 페이지에서 교사용 검토 초안임을 표시한다. 학생 배포 확정본이나 검증 인증서로 표시하지 않는다.

### 1.4 AI 튜터 학습 증거

- 최초 응답·힌트 사용·독립 후속 응답·지연 후속 응답·교사 검증을 구분한다.
- 같은 문항의 외형적 revision 변경만으로 독립 평가가 되지 않도록 문항 지문·선택지를 정규화한 내용의 해시를 대조한다.
- 독립 응답 분류 순서와 같은 목표개념의 증거 결속을 수정했다. 교사 검토 클릭만으로 실제 제공되지 않은 힌트 증거를 자동 생성하지 않는다.
- 학습 후보 적격성, 실제 학습 사용 영수증, 모델 승격은 별개이다. 이번 작업으로 실제 GPU 훈련, 가중치 갱신 또는 모델 승격을 실행하지 않았다.

### 1.5 백업 실행 코드

- 등록된 자산의 서버·Drive 저장과 대조 검증, 복원 검증, 결과 영수증을 위한 실행 경로를 구현했다.
- 관리자 전용 상태·실행 API와 명시적으로 활성화하는 30분 주기 작업을 연결했다. 필수 저장 설정이 충족되지 않으면 운영 백업 성공으로 처리하지 않는다.
- 구체 구성·보존 조건은 `docs/BACKUP_RUNTIME_20260928.md`를 따른다.
- **운영 manifest, 승인된 Shared Drive 접근 자격정보, 영속 mount가 연결되지 않았다. 현재 운영 자동백업이 설치·실행·복구 검증되었다는 뜻이 아니다.**

### 배포를 막는 실제 사유

현재 SQLite 파일은 영속 볼륨이 없는 기존 컨테이너에 존재한다. 새 코드를 배포하거나 경로를 빈 볼륨으로 바꾸면 기존 데이터를 잃을 수 있다. 새 백업 코드를 배포해야만 기존 데이터를 백업할 수 있다는 이유로 먼저 재배포하지 않는다. 환경변수에 경로를 적는 것만으로 기존 파일이 이동하거나 볼륨이 생성되지 않는다.

## 4. 다음 실행 순서

1. Draft PR에 이번 코드·테스트·운영 제약을 함께 제시한다. PR 번호와 URL은 생성 성공 후 별도로 기록한다.
2. 기존 실행 컨테이너의 SQLite 및 필요한 관련 상태를 승인된 접근 경로로 내보낸다. 일관된 SQLite 사본, 해시, 읽기·복원 대조를 확보한다. 현재는 내보내기 완료를 주장할 수 없다.
3. 영속 저장 위치를 실제로 구성하고 기존 데이터를 옮긴 뒤, 이전 파일과 새 저장소의 데이터 일치를 확인한다. 비용이나 새로운 권한이 필요한 구성은 구체 대상을 먼저 확인한다.
4. 등록 manifest와 승인된 Drive 대상·자격정보를 연결하고, 수동 백업 및 복원 대조를 성공시킨다. 그 후 주기 작업을 활성화한다.
5. 보존·마이그레이션 증거와 변경 검토가 충족된 뒤 배포한다. 배포 후 실제 운영 버전과 인증·수업 공개·버전 불일치 차단을 확인한다.
6. 공급자별로 실제 API 인증·모델 권한·할당량·보존 조건을 확인한 뒤 명시적으로 선택한 공급자의 최소 출제·독립 검증을 확인한다. 키 재발급·교체·결제 또는 허위 ZDR 승인을 이번 작업의 완료 수단으로 사용하지 않는다.
7. 전자칠판 실기기와 교사 업무 흐름을 별도로 확인한다. 개별 교사 계정·기관 권한·좌석·과금 등 상용 다중사용자 기능은 별도 범위로 관리한다.
