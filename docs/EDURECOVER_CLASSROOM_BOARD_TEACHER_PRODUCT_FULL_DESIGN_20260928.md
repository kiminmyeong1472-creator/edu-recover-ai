# EduRecover Classroom Board 교사용 상품 전체설계

- 기준일: 2026-09-28
- 구현 단계: 단일 교사 파일럿 상품
- 운영 주소: `/classroom`
- 기존 관리자 튜터 주소: `/tutor`
- 학생 개인정보 기본값: 별칭 또는 번호

## 1. 결론

기존 시청각자료와 전자칠판 프로토타입을 `EduRecover Classroom Board`라는
교사용 독립 화면으로 분리하였다. 교사는 영상 또는 한국어 TTS 원고, 문제, 선택지,
오답 원인, 산파식 확인 질문을 입력하여 전자칠판 수업을 만들 수 있다. 생성된 수업은
전자칠판 화면, 교사 콘솔, 학생 참여 화면으로 나뉘며 각각 별도 토큰으로 보호된다.

현재 단계는 김대표가 직접 운영·검증하는 단일 교사 파일럿이다. 별도 상품 화면과
상품 전용 생성 경로는 완성했지만, 다수 교사의 회원가입·기관별 결제·좌석관리 기능은
아직 연결하지 않았다. 따라서 상용 다중사용자 서비스 완료로 표시하지 않는다.

## 2. 상품 정의

### 2.1 상품명

`EduRecover Classroom Board`

### 2.2 대상

- 학교 교사
- 학원 강사
- 전자칠판이 없는 일반 교실에서 노트북과 프로젝터를 사용하는 교사
- 학생 휴대폰 또는 태블릿의 QR 참여가 필요한 수업

### 2.3 해결하는 문제

교사가 동영상만 재생하거나 설명만 전달하는 방식에서 벗어나, 학생의 오개념을
확인하고 짧은 설명 뒤에 다시 질문하여 이해 여부를 확인할 수 있게 한다. 전자칠판이
터치백을 지원하지 않아도 학생은 가명과 QR 링크로 응답할 수 있다.

### 2.4 핵심 수업 구조

1. 문제와 조건 확인
2. 학생의 최초 판단 또는 오답 원인 확인
3. 짧은 영상 또는 한국어 TTS 설명
4. 산파식 확인 질문
5. 응답에 따른 설명 재진입 또는 다음 단계 이동
6. 같은 개념을 다른 맥락에서 확인하는 전이 재시험

정답이나 공식을 먼저 제시하지 않고, 학생이 문제 상황·주어진 조건·구해야 하는 것과
각 문장·그림·수치의 의미를 자기 말로 설명한 뒤 식이나 판단을 세우게 하는 자체 AI
교사 원칙을 유지한다.

| 학생 QR 참여 | 가능 | 가능 |
| 실시간 응답 집계 | 가능 | 가능 |

모델 승격과 롤백은 상품 화면에서 분리하고 관리자 통제영역에 남긴다.

## 4. 지원 장치와 연결 방식

### 4.1 지원 장치

- 전자칠판 내장 브라우저
- OPS Windows PC
- 일반 Windows 또는 macOS 교사 PC
- 노트북과 태블릿
- 학생 휴대폰과 태블릿

### 4.2 실행 방식

| 실행 방식 | 설명 |
|---|---|
| DIRECT BOARD WEB | 전자칠판 브라우저에서 직접 실행 |
| WINDOWS OPS WEB | 전자칠판 내장 Windows OPS에서 실행 |
| CAST | Miracast AirPlay Google Cast 또는 제조사 캐스트로 미러링 |
| WIRED MIRROR | HDMI 또는 USB C로 교사 화면을 미러링 |
| TEACHER DEVICE | 교사 기기에서 수업을 운영하고 별도 디스플레이로 표시 |

브라우저 애플리케이션은 Miracast나 HDMI 연결 자체를 강제로 설정하지 않는다. 운영체제
또는 전자칠판 제조사의 연결 기능을 사용한 뒤 EduRecover 화면이 표시와 상호작용을
담당한다.

## 5. 화면 구성

### 5.1 교사용 상품 홈

- 수업 제목과 교실 별칭 입력
- 전자칠판 실행 방식과 연결 방식 선택
- 문제와 선택지 입력
- 정답 입력
- 오답 원인 입력
- 영상 주소 입력 또는 TTS 원고 입력
- 자동 멈춤 시점 입력
- 산파식 확인 질문 입력
- 전자칠판 수업 생성

### 5.2 전자칠판 화면

- 현재 수업 단계와 큰 글씨 설명
- MP4 WebM 또는 YouTube 개인정보 강화 임베드 재생
- 영상이 없으면 브라우저 한국어 음성합성
- 재생 일시정지 이전 다음 전체중지
- 판서 캔버스 전환
- 학생 참여 QR과 주소
- 현재 응답 분포
- 장치 터치 포인터 전체화면 음성합성 지원 여부

### 5.3 교사 콘솔

- 전자칠판 화면 열기
- 수업 단계 직접 이동
- 실시간 학생 응답 집계
- 개인정보 원칙 표시
- 관리자 강화학습 내부정보 미표시

### 5.4 학생 화면

- 실명 대신 가명 또는 번호
- 현재 단계의 질문과 선택지
- 선택적 확신도
- 선택적 판단 이유
- 응답 전송 상태

학생 상태 API에서는 정답, 내부 분기표, 오답 경로, 콘텐츠 revision, 신뢰상태와
학습용 내부 식별자를 제거한다.

## 6. 시스템 구조

### 6.1 실행 흐름

교사용 상품 홈에서 수업을 만들면 서버가 수업 ID, 교사 토큰, 학생 참여 토큰을 각각
발급한다. 교사와 전자칠판은 교사 토큰으로 전체 수업상태와 집계에 접근하고, 학생은
참여 토큰으로 공개 가능한 수업 조각만 조회하고 응답한다.

### 6.2 주요 구성요소

| 구성요소 | 책임 | 코드 |
|---|---|---|
| Teacher Product Router | 교사용 독립 상품 주소와 생성 경로 | `app/classroom_tutor.py` |
| Classroom Tutor Router | 수업 상태 응답 이벤트 관리자 기능 | `app/classroom_tutor.py` |
| Owner Authentication | 단일 교사 파일럿 접근 통제 | `app/services/owner_basic_auth.py` |
| Teacher Platform | 기존 출제플랫폼에서 상품 진입 | `app/pilot_page.py` |
| Teacher View Filter | 무료 교사 화면에서 관리자 상품 링크 제거 | `app/services/teacher_view.py` |
| Tutor Learning Ledger | 관리자 전용 학습후보와 영수증 | `app/training/tutor_ledger.py` |

### 6.3 저장소

- `classroom_tutor.sqlite3`: 수업 세션, 학생 응답, 이벤트
- `ai_tutor_training.sqlite3`: 비식별 노출, 근거, 보상, 적격성 revision

수업 운영 데이터와 AI 훈련 통제 데이터를 논리적으로 분리한다. 학생 응답은 자동으로
모델 가중치를 변경하지 않는다.

## 8. 보안과 개인정보

1. 교사 토큰과 학생 참여 토큰을 분리한다.
2. 토큰이 없는 수업 상태 요청은 거부한다.
3. 학생 토큰으로는 정답과 내부 제어정보를 반환하지 않는다.
4. 학생 실명 입력을 요구하지 않는다.
5. 토큰이 URL에 포함된 화면은 `Referrer Policy no-referrer`와 `Cache Control no-store`를
   사용한다.
6. 외부 AI에는 전체 내부 데이터베이스를 보내지 않고 현재 작업에 필요한 최소 조각만
   전달한다.
7. 외부 AI 제공자 호출은 명시적 선택, 허용목록, 개인정보 게이트를 통과한 경우에만
   수행한다.
8. 학생 응답은 교사검증과 별도 적격성 판단 전에는 AI 훈련에 실제 사용하지 않는다.

현재 데이터베이스의 교사 토큰과 참여 토큰은 서버 저장소 안에 보관된다. 다중 기관
상용화 전에는 토큰 해시 저장, 교사 계정별 소유권, 기관별 데이터 분리, 보존기간과
삭제정책을 추가해야 한다.

## 9. AI 튜터와 강화학습 연결

교사용 상품은 AI 튜터의 수업 전달 표면이다. 강화학습 통제면은 관리자 영역에
남긴다.

- 응답 직후 자동 가중치 갱신 없음
- 비식별 별칭과 서버 비밀 salt를 사용한 학습자 pseudonym
- 최초 응답과 피드백 후 응답 분리
- 독립 전이문항 별도 표시
- 교사검증 revision 추가
- 콘텐츠 결함 발생 시 후속 revision 생성
- 목적별 ELIGIBLE HOLD INELIGIBLE 판정
- 실제 학습 사용 시 별도 영수증
- Socratic tutoring 특허와 FTO 검토가 완료되지 않은 용도는 fail closed

접속 학생 수, 저장비용과 지원비용을 측정한 뒤 별도 상품정책으로 결정한다.
