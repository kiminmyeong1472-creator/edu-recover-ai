# 드림지킴이 논술 적용 모듈

`app/services/dreamkeeper_essay.py`는 교사가 제공한 문제·실제 학생 답안·교사 승인 기준표를 같은 버전으로 묶어 점수 제안을 검사합니다. Python 표준 라이브러리만 사용하며 모델 호출, 네트워크 접속, 이미지 문자 인식, 운영 서비스 배포를 수행하지 않습니다. 자체 엔진과 별도 모듈로 동작합니다.

이 코드는 기준표나 점수를 스스로 만들지 않습니다. 대학 공식 기준표·공식 배점이 포함되어 있지 않습니다. 아래 예와 시험의 문항·학생·기준표·점수는 모두 **가상 자료**입니다.

## 교사용 기본 루브릭 제안 초안

다음 기준표는 교사가 실제 수업용 기준표를 준비할 수 있도록 이번에 제안하는 **100점 만점 초안**입니다. 대학 공식 채점표나 사용자가 지정한 공식 배점이 아닙니다. 특정 문항·학년에서 타당성이 검증된 기준표도 아닙니다. 교사가 실제 문제의 요구, 제시자료, 학년과 학습 목표를 확인하고 문구·구간·배점을 수정·승인하기 전에는 학생 성적 확정에 사용하지 마십시오. 모듈이 이 표를 자동으로 승인하거나 기본 성적으로 적용하지 않습니다.

| 항목·배점 | 상 구간 | 중 구간 | 하 구간 | 답안에서 요구하는 증거 |
| --- | --- | --- | --- | --- |
| 문항 조건 이해 **20점** | **16–20점**: 요구한 과제·대상·범위와 필수 조건을 모두 반영하고, 요약·비교·평가 등 요구된 동작을 정확히 수행합니다. | **8–15점**: 핵심 과제는 수행하나 필수 조건 일부를 누락하거나 범위를 불필요하게 넓힙니다. | **0–7점**: 다른 질문에 답하거나 핵심 조건을 잘못 읽어 요구한 과제를 거의 수행하지 못합니다. | 조건을 반영한 문장과 문항의 해당 조건을 교사가 대조합니다. 답안의 인용 시작·끝 위치를 남기고, 누락 판단은 답안 전체를 확인한 범위와 함께 기록합니다. |
| 주장과 관점 **20점** | **16–20점**: 문제에 대한 입장이 분명하고 일관되며 비교 관점이나 대안이 그 입장을 구체화합니다. 관점이 익숙하다는 이유만으로 감점하지 않습니다. | **8–15점**: 입장은 확인되나 범위·기준이 모호하거나 관점의 차이를 충분히 설명하지 못합니다. | **0–7점**: 입장을 찾기 어렵거나 서로 모순되는 주장을 조정 없이 나열합니다. | 입장을 밝힌 문장, 비교 기준 또는 대안을 제시한 문장을 각각 인용합니다. 특이한 관점은 그 관점의 원문과 설명을 별도로 기록합니다. |
| 근거와 자료 활용 **25점** | **20–25점**: 필요한 제시자료를 정확히 읽고 주장과 관련된 근거로 사용하며, 인용·요약·자기 해석을 구별합니다. | **10–19점**: 관련 자료를 사용하나 일부 해석이 부정확하거나 근거와 주장 사이의 연결 설명이 부족합니다. | **0–9점**: 필수 자료를 거의 활용하지 않거나 원문과 다른 내용·확인할 수 없는 내용을 핵심 근거로 제시합니다. | 자료를 사용한 답안 문장을 인용하고 교사가 제시자료 원문의 위치와 대조합니다. 답안의 정확한 인용만으로 자료 해석이 옳다고 확정하지 않습니다. |
| 논리 구성 **25점** | **20–25점**: 주장→이유→근거→결론의 연결이 명확하고, 필요한 반론·예외를 다루며 결론이 근거의 범위를 넘지 않습니다. | **10–19점**: 전체 흐름은 있으나 일부 비약·반복·미해결 반론이 남습니다. | **0–9점**: 근거 없이 결론으로 뛰거나 핵심 모순·인과 혼동 때문에 주장을 지지하기 어렵습니다. | 연결을 평가할 주장 문장과 이유·근거·결론 문장을 함께 인용합니다. 문장 하나의 존재가 아니라 그 문장들 사이의 관계를 교사가 확인합니다. |
| 표현 **10점** | **8–10점**: 문장이 명확하고 문단이 구별되며 용어·지시대상이 일관되어 의미를 무리 없이 이해할 수 있습니다. | **4–7점**: 일부 어색한 표현·지시대상 불명확·문단 연결 문제가 있으나 핵심 의미는 파악됩니다. | **0–3점**: 표현이나 문단 구성이 뜻을 자주 가려 핵심 의미를 파악하기 어렵습니다. | 문제를 일으킨 표현 또는 명료한 표현의 실제 문장을 인용하고, 의미 이해에 어떤 영향을 주는지 구체적으로 기록합니다. 단순 취향을 감점 근거로 삼지 않습니다. |

다섯 항목의 최대 배점 합계는 **20 + 20 + 25 + 25 + 10 = 100점**입니다. 상·중·하 구간 안의 특정 점수는 AI가 자의적으로 고르지 않도록 교사가 문항별 충족 조건과 부분 점수 규칙을 추가해야 합니다. 위 구간은 정수 점수를 전제로 한 제안이며 소수 배점을 쓰려면 경계와 단위를 교사가 먼저 정해야 합니다. 읽기나 자료 대조가 미확정인 경우는 하 구간이나 0점으로 대신 처리하지 않고 **확정 보류**로 남깁니다. 근거가 없는 점수를 채우기 위해 인용문을 만들어서는 안 됩니다.

### 창의성과 논거 타당성은 따로 관찰

창의성 관찰에는 특이한 관점의 원문, 바꿔 본 전제·비교 대상·연결 방식, 문제 해결에 기여하는 이유를 남깁니다. 논거 타당성 관찰에는 그 관점을 뒷받침하는 자료·추론, 반례와 한계를 남깁니다. 새로운 관점이 있어도 틀린 사실이나 성립하지 않는 추론을 정답 근거로 인정하지 않습니다. 반대로 익숙한 관점이라도 문항 요구와 논증 조건을 충족하면 그 조건에 맞게 평가합니다.

위 100점 초안에서 창의성은 자동 가산점이 아닙니다. 교사가 ‘주장과 관점’ 항목 안의 별도 관찰을 어떻게 점수와 연결할지 또는 독립 항목으로 둘지 정하고, `creativity`와 `argument_validity`의 구분 및 문항별 배점을 승인한 뒤 코드의 기준표로 등록해야 합니다. 이를 정하지 않은 표를 모듈에 넣기 위해 AI가 임의로 새 항목이나 점수를 만들어서는 안 됩니다.

### 학생 점수와 AI 행동 평가·보상은 별도 기록

이 100점 초안은 **학생 답안의 성취를 평가하기 위한 제안**입니다. G1~G4 등 AI 행동의 평가·보상 점수는 AI가 사용자 지시·검증 절차 등을 어떻게 수행했는지에 관한 별도 기록입니다. AI의 행동 평가가 높아졌다는 이유로 학생 점수를 올리거나, 학생 점수 하락을 AI의 제약 위반 확정 근거로 삼지 않습니다. 두 점수의 항목·분모·대상·개정 번호와 승인 기록을 구별하고 자동 환산하지 마십시오. 해당 AI 행동 기준의 구체 정의는 별도 승인된 기준을 그대로 사용하며 이 논술 초안에서 새로 정하지 않습니다.

## 입력과 검사

| 입력 | 저장하는 내용 | 확인할 조건 |
| --- | --- | --- |
| `TeacherContext` | 교사·수업 맥락 식별자, 개정 번호, 교사 지시 | 제안 당시와 현재 맥락이 같아야 합니다. |
| `EssayProblem` | 문제 원문, 개정 번호, 읽기 확인 상태 | 원문이 바뀌거나 읽기가 미확정이면 확정을 보류합니다. |
| `EssayAnswer` | 학생·답안 식별자, 실제 답안 원문, 개정 번호 | 같은 버전이라고 주장해도 원문이나 학생이 달라지면 이전 제안을 거부합니다. |
| `TeacherRubric` | 항목키, 설명, 최소·최대 배점, 적용 문제 버전, 승인 교사 | 현재 교사가 승인한 해당 문제 버전의 기준표만 사용합니다. |
| `AnswerEvidence` | 해당 답안의 문자 시작·끝 위치, 정확한 인용, 답안 해시 | 답안 식별자·개정 번호·전체 원문 해시가 맞고 `text[start:end] == quote`여야 합니다. |
| `CriterionScore` | 제공된 기준표 항목키, 제안점수, 인용 근거, 제안 이유 | 항목 누락·중복·새 항목 생성, 배점 범위 위반, 근거 누락을 거부합니다. |

해시는 문서 내용을 구별하는 계산값입니다. 답안 원문은 공백·줄바꿈을 고치지 않은 UTF-8 문자열로 계산합니다. `start`는 포함하고 `end`는 제외합니다. 위치는 Python 문자열의 유니코드 문자 단위이며 바이트나 브라우저의 UTF-16 위치와 같다고 가정하지 않습니다. 외부 화면에서 받은 위치는 등록한 **정확한 답안 문자열** 기준으로 변환해야 합니다.

문제·답안·기준표의 `reading_status` 기본값은 `uncertain`입니다. 글씨나 전사 결과를 확인한 뒤에만 신뢰할 수 있는 교사 처리 경로에서 `confirmed`로 기록하십시오. 이 모듈 자체가 글씨를 읽거나 전사의 정확성을 판정하지는 않습니다.

기준표에는 `creativity`(특이한 관점·대안 연결)와 `argument_validity`(주장과 근거의 타당한 연결)를 서로 다른 항목으로 공급해야 합니다. 나머지 항목에는 `other`를 사용할 수 있습니다. 기준표에 두 항목이 없으면 모듈이 배점을 새로 넣지 않고 `DIMENSIONS_NOT_SEPARATE`로 보류합니다. 실제 기준표를 유지하면서 이 구분을 어떻게 기록할지는 교사가 정해야 합니다.

점수는 `Decimal`, 정수 또는 소수 문자열로 받습니다. 이진 실수의 반올림 혼동을 피하기 위해 `0.1` 같은 float 대신 `"0.1"`을 입력하십시오. `NaN`, 무한대, 참·거짓 값은 받지 않습니다. 합계는 항목 점수의 합으로 계산하고, 별도로 전달된 합계가 있으면 그 합과 다시 대조합니다.

## 제안과 교사 확정

1. `propose_score(...)`는 현재 네 문서의 내용과 버전을 묶은 `ai_proposed` 제안을 만듭니다.
2. `review_score(...)`는 버전·인용·배점·합계를 검사합니다. 통과해도 제안 상태는 `ai_proposed`입니다.
3. 교사가 실제로 검토한 후 서버에서 인증한 교사 식별자와 결정 기록을 `confirm_score(...)`에 전달하십시오. 이때 현재 문서를 다시 검사합니다.
4. 표시·내보내기·성적 반영 직전에 `review_confirmation(...)`을 다시 호출하십시오. 답안·기준표·문제·교사 지시가 달라졌으면 이전 확정 기록으로 새 버전을 승인하지 않습니다.

교사 식별자 문자열과 결정 기록은 인증 수단 자체가 아닙니다. 로그인·교사 권한 확인, 원문 승인과 변경 기록, 성적 저장은 신뢰할 수 있는 서버에서 별도로 처리해야 합니다. 모델에 `confirm_score`나 교사 인증 정보를 도구로 노출하지 마십시오.

정확한 인용이 있다고 해서 인용과 점수 이유의 의미 관계가 입증되는 것은 아닙니다. 검사 통과는 원문의 동일성·문자 위치·숫자 합계가 맞는다는 뜻입니다. 논증의 타당성·창의성·채점 공정성·실제 학생의 이해도는 교사가 별도로 확인해야 합니다. 자동 환각 차단이나 의미적 진실성을 증명한 구현으로 설명하지 마십시오.

## 산파식 지도 순서

`GuidanceProgress`는 다음 순서를 보존하며 각 단계의 학생 응답 없이는 다음 단계로 넘어가지 않습니다.

1. `korean_interpretation`: 문제 문장을 한국어로 해석합니다.
2. `conditions_and_target`: 주어진 조건과 구해야 할 양을 문장으로 구별합니다.
3. `diagram_meaning`: 그림·도표의 대상과 관계를 문장으로 설명합니다. 그림이 없으면 없다고 기록합니다.
4. `student_equation`: 학생이 직접 식 또는 논증을 작성합니다.
5. `teacher_review`: 교사가 해석과 식·논증을 확인합니다.

모듈의 고정 질문에는 정답·공식·식을 미리 제시하는 내용이 없습니다. 단계별 응답은 입력 순서의 기록이며 이해도 판정이 아닙니다. 외부 모델이 작성한 임의의 지도 문장에 답이나 공식이 섞였는지 이 모듈이 의미적으로 검사하지는 않습니다. 외부 모델을 붙일 때도 선제공 금지와 위 순서를 유지하고 교사가 확인해야 합니다.

## 실제 실행 예

저장소 루트에서 아래 가상 예를 실행하십시오. 제안 점수도 가상 교사가 미리 지정한 값이며 모델이 채점한 값이 아닙니다.

```python
from dataclasses import replace
from app.services.dreamkeeper_essay import (
    AnswerEvidence, CriterionScore, EssayAnswer, EssayProblem, GuidanceProgress,
    RubricCriterion, TeacherContext, TeacherRubric, confirm_score, propose_score,
    review_confirmation, review_score,
)

problem = EssayProblem("fictional-problem", 1, "도서관 운영 제안을 논증하십시오.", "confirmed")
context = TeacherContext("fictional-class", 1, "fictional-teacher", "근거와 관점을 구별합니다.", problem)
answer = EssayAnswer("fictional-answer", 1, "fictional-student",
                     "야간 이용자를 조사해야 한다. 이동 도서관도 대안이다.", "confirmed")
rubric = TeacherRubric(
    "fictional-rubric", 1, problem.problem_id, problem.revision,
    (RubricCriterion("perspective", "대안 관점", "creativity", "3"),
     RubricCriterion("reasoning", "주장과 근거 연결", "argument_validity", "7")),
    approved_by=context.teacher_id, reading_status="confirmed",
)
first = AnswerEvidence.from_answer(answer, 0, answer.text.index(".") + 1)
second = AnswerEvidence.from_answer(answer, answer.text.index("이동"), len(answer.text))
proposal = propose_score("fictional-proposal", context, answer, rubric, (
    CriterionScore("perspective", "2", (second,), "가상 교사의 관점 점수 제안"),
    CriterionScore("reasoning", "5", (first,), "가상 교사의 논증 점수 제안"),
))
review = review_score(proposal, context, answer, rubric)
print(proposal.status, review.valid, proposal.calculated_total)
# 가상 예에서 교사의 명시적 결정을 기록합니다. 실제 서비스에서는 인증이 먼저입니다.
confirmed = confirm_score(proposal, context, answer, rubric,
                          teacher_id=context.teacher_id, confirmation_receipt="fictional-teacher-click")
print(confirmed.status)
print("old_confirmation_valid_after_rubric_change:",
      review_confirmation(confirmed, context, answer, replace(rubric, revision=2)).valid)
progress = GuidanceProgress()
progress = progress.record_student_response(progress.stage, "학생이 문제를 자기 말로 해석한 내용")
print("next_guidance_stage:", progress.stage)
```

## 자체 엔진과의 연결

`submit_score_proposal(...)`은 `DreamkeeperEngine.model_port(binding)`의 후보 제출 기능만 사용합니다. 자체 엔진의 목표 생성·변경·승인·소비 권한을 논술 모듈에 추가하지 않습니다.

- 신뢰할 수 있는 서버에서 `source_documents(context, answer, rubric)`의 네 문서를 각각 엔진의 원천자료 필드에 등록하십시오. 반환된 **필드 개정 번호**와 `ScoreBinding.capture(...).document()`의 문서 해시로 역할별 `EngineSourceLink`를 만드십시오.
- 어댑터는 현재 점수 제안을 검사하고 엔진에서 읽은 실제 필드 값의 해시와 필드 개정 번호도 대조합니다. 엔진은 제출 순간 해당 개정 번호를 다시 검사합니다.
- 네 역할은 `teacher_context`, `problem`, `answer`, `rubric`입니다. 빠진 역할, 같은 원천 필드를 두 역할로 쓰는 연결, 다른 문서 값이나 버전은 거부합니다.
- 후보 목적은 `essay_score_proposal`이고 내용의 상태는 `ai_proposed`입니다. 엔진이 후보를 저장하거나 소비했어도 그 사건이 교사 확정을 대신하지 않습니다.
- 실제 교사 검토와 인증을 거친 서버만 교사 확정 기록 및 엔진의 검토·소비 절차를 수행하도록 구성하십시오. 나중에 원천자료가 정정되면 엔진이 해당 필드를 사용한 이전 후보를 보류합니다.

현재 모듈은 동시 사용자의 로그인·보안 경계나 브라우저 상품 화면이 아닙니다. 개인정보가 포함된 답안의 외부 전송도 수행하지 않습니다.
