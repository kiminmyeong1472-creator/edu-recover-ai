# 양자난수 선불 횟수 제한

선불 입금을 확인한 생활앱 계정에만 ANU 양자난수 호출 횟수를 할당합니다.
사용자 지시 원문은 “이거 라우터로 호줄 회수제안해야 돼. 유료선납에 한해 회수할당”입니다.
2026년 10월 19일 한국시간 지시를 반영했습니다.

## 적용 범위와 계산 단위

라우터는 외부 프로그램으로 요청을 보내기 전에 사용 자격과 남은 횟수를 확인하는 통로입니다.
이번 통로는 ANU 양자난수에만 적용합니다. 기존 27개 모델과 OpenRouter의 경로는 보존합니다.
고객에게 받는 선불금과 ANU가 AWS를 통해 청구하는 사용료는 별개입니다.
ANU 구독 자체를 선불제나 정액제로 변경하지 않습니다.

한 번의 ANU 요청을 1회로 셉니다. 이 요청으로 난수 1개부터 1,024개까지 받을 수 있습니다.
이번 코드는 0부터 65,535까지의 정수만 요청합니다. 여러 사용자의 요청을 합치거나
같은 난수를 다른 사용자에게 나누어 주지 않습니다. 사용자별 판매가격과 상품별 횟수는
아직 정해지지 않았으므로 코드가 금액으로 횟수를 자동 계산하지 않습니다.

## 입금 확인과 횟수 등록

결제업체가 아직 정해지지 않았으므로 관리자가 실제 입금 내역을 확인한 뒤 등록합니다.
`POST /owner/qrng/prepayments`는 기존 관리자 인증이 필요합니다.
`account_id`는 실제 생활앱 계정 식별번호, `provider`와 `reference`는 결제 경로와
고유 결제번호, `calls`는 할당 횟수, `amount_minor`는 통화의 최소 단위 금액입니다.
예를 들어 KRW 1,000은 1,000원, USD 100은 1달러입니다.
`currency`는 KRW 또는 USD처럼 세 글자의 대문자 통화 코드입니다.
`settlement_checked=true`는 관리자가 입금을 확인했다는 명시적 기록입니다.
이는 은행 조회나 결제업체의 자동 검증을 수행했다는 뜻이 아닙니다.
카드번호나 인증키를 결제번호로 입력하지 마십시오.

로그인한 고객은 이 관리 경로를 사용할 수 없습니다. 고객이 제출한 `paid=true` 값으로
할당하지 않습니다. 결제번호는 내용 확인값인 SHA-256으로 저장하며, 같은 결제번호를
다시 등록해도 횟수가 늘지 않습니다. 계정·금액·통화·할당량이 바뀐 재등록은 거부합니다.
결제업체를 선택한 뒤에는 해당 업체의 서명과 최종 결제 상태를 서버에서 검증하는
별도 연결이 필요합니다. 현재 자동 결제·자동 충전·가격표 생성 기능은 없습니다.

## 호출 제한과 중복 방지

`GET /life/api/qrng/quota`는 로그인한 본인의 남은 횟수만 보여 줍니다.
`POST /life/api/qrng/numbers`에는 `request_id`와 `length`만 제출합니다.
계정은 로그인 정보에서 서버가 정합니다. 고객이 계정이나 제공업체 주소를 바꿀 수 없습니다.
`request_id`는 같은 요청을 다시 보냈는지 구별하는 8~80자의 고유 식별번호입니다.

남은 횟수 확인·1회 차감·요청 기록을 하나의 데이터베이스 처리로 묶습니다.
차감 기록이 저장된 뒤에만 ANU로 전송합니다. 동시에 여러 요청이 들어와도 할당량을
넘길 수 없습니다. 잔여 횟수가 없으면 402, 서비스 전체 일일 한도에 도달하면 429로
차단합니다. 같은 요청번호는 성공·진행·오류 상태와 관계없이 다시 전송하지 않습니다.

시간 초과나 응답 오류는 ANU가 이미 처리했는지 알 수 없으므로 `UNKNOWN`으로 기록하고
1회 차감을 유지합니다. 자동 재시도·자동 횟수 반환·다른 업체로 우회 호출하지 않습니다.
숫자 결과는 저장하지 않으므로 같은 요청을 다시 보내도 원래 결과를 돌려주지 않습니다.
관리자가 업체의 청구·처리 내역을 확인한 뒤 처리해야 합니다.

환불·결제 취소를 확인한 관리자는 `POST /owner/qrng/prepayments/revoke`로 해당 결제의
미사용 횟수를 취소할 수 있습니다. 이미 예약·전송한 요청은 되돌리지 않습니다.
이 경로는 이용권만 취소하며 실제 금전 환불은 수행하지 않습니다.

## 실행 설정과 보관

세 설정을 모두 서버에 준비해야 실제 호출할 수 있습니다.
`ANU_QRNG_ENABLED=true`는 호출 통로를 켜는 값입니다.
`ANU_QRNG_API_KEY`에는 ANU 유료 계정의 인증키를 서버에만 보관합니다.
`ANU_QRNG_DAILY_CALL_LIMIT`에는 관리자가 정한 서비스 전체 하루 호출 한도를
1~999,999 범위의 정수로 지정합니다. 이 문서는 실제 운영 한도나 판매가격을 정하지 않습니다.
일일 한도는 세계 표준시간 UTC 자정, 한국시간 오전 9시에 갱신합니다.
키만 추가하거나 선불 횟수만 등록해도 자동으로 켜지지 않습니다.

횟수 기록은 기존 영속 저장공간 아래 `qrng/prepaid.sqlite3`에 보관합니다.
영속 저장공간은 재배포 뒤에도 데이터를 유지하는 디스크입니다.
기존 백업 대상 목록과 저장 현황에 이 파일을 추가했습니다.
예약 횟수와 결제 참조 기록을 같은 파일에 두어 이 파일의 온라인 스냅샷으로
둘을 함께 보관할 수 있습니다. 실제 백업 스케줄이나 Drive 인증을 켠 것은 아닙니다.
데이터베이스를 오래된 시점으로 되돌리면 이미 쓴 횟수가 다시 생길 수 있으므로
복원 후에는 호출을 끄고 복원 시점 이후 결제·호출 기록과 대조한 뒤 재개해야 합니다.
여러 작업 프로세스는 같은 SQLite 파일을 사용해야 합니다. 서로 다른 디스크를 쓰는
여러 서버에 복제해 실행하는 구조에는 공통 결제 데이터베이스 연결이 추가로 필요합니다.
