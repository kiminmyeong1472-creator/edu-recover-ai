정리일: 2026-09-14

1. 가장 먼저 무엇을 붙일 것인가
공통 정책 01_CURRENT_POLICY_v9_v7_2.txt를 먼저 읽힌다. 그 다음 목적에 맞는 파일만 첨부한다.
모든 파일을 한 대화에 함께 넣지 않는다. 소스코드/출제목표/검증문항의 역할을 분리한다.

2. 목적별 첨부
가. 기존 세 프로그램 이식/개발
02_TRICORE_Node18_LEGACY_SOURCE.txt + 03_TRICORE_Node18_EXECUTION_PROMPT.txt
포함: EduRecoverAI v3.19.0 코어/확장, 특허검증 프로그램, AI백신1, 통합 실행기.
2026-09-08 원본을 이름만 바꾸어 바이트 그대로 제공한다. 이것을 9월14일 최신 통합개발본이라 부르지 않는다.
Node.js 18.20.4 이상, 외부패키지0개를 목표로 작성된 원본이다.
구형 교육 승인정책이나 검증독립 설명과 현행 정책이 다르면 그 차이를 보고한다. 읽기만으로 코드를 고친 것으로 간주하지 않는다.

나. 최신 v9 교차출제/3-Solver 실행기 이식/개발
04_v9_DEVELOPER_SOURCE_ONLY.txt
v9 코드/설정/규격/시험과 v7.2 승인범위 참조코드. 개발자 대화에서만 사용한다.
원본 기준 Python 3.11 이상, jsonschema==4.26.0. Node18 전용/패키지0개 조건과는 다르다.
이번에 해당 조건에 맞게 포팅하지 않았다. 코드만 추출했으며 운영서버 배포를 하지 않았다.
실제 문항 기준정답 DB 및 API 비밀정보는 제외했다. 관리자 키대조까지 실행하려면 권한 있는 관리자 보관자료와 실행환경 연결이 별도로 필요하다.

다. 현재 Gemini 수학 검증자에게 줄 것
06_MATH862_S2_GEMINI_NO_GOLD.txt
원문/선택지862개 + S2 지시문 + 반환 JSON 규격. 하나의 검증자 역할만 맡긴다.
05_MATH862_S1_NO_GOLD.txt와 07_MATH862_S3_NO_GOLD.txt는 각각 별도 검증자에게 전달한다.
기본 배치는 S1 GPT / S2 Gemini / S3 GPT이며 서로 다른 실제 모델버전3개와 제공사2개가 필요하다.
세 파일을 한 Gemini 대화에 붙여 세 사람처럼 답하게 해서는 안 된다.
862개는 원본 레코드 수이다. 문장과 선택지집합이 같은 내용(선지기호·순서 무시)을 합치면810개이며, 선지기호까지 구분하면860개이다. 다만 원본 ID와 계보 보존을 위해 레코드를 삭제하지 않았다.
한 개 TXT에 자료은행을 담았다는 사실은 각 문항의 신규 stateless 실행 또는 의미검증 완료를 뜻하지 않는다.

라. Gemini에게 새 문제를 출제시킬 것
08_AUTHOR_TARGETS862_NO_GOLD.txt
출제목표862개. 기존 기준정답은 없지만 단서/오답 설계참고가 있으므로 검증자에게 넘기지 않는다.
새 문제와 제안정답을 받은 관리자가 문제부분만 분리하여 교차검증에 넘긴다.

마. 영어 우선 검증
09_ENGLISH15_BLIND_NO_GOLD.txt + chart_H1.png + chart_H2.png + chart_H3.png
학년별5개씩 새 후보15개. 세 PNG는 원본 도표이며 문제입력의 해시와 일치한다.
기존 영어420개 전체/전학년 완료본이 아니다. 원기출·응답자료 전체도 이번 묶음에 포함하지 않았다.
과목순서: 영어 → 수학 → 국어 → 과학. 영어 듣기1~17은 삭제하지 않고 보류하며 독해18~45를 우선한다.

3. 공통 정책의 핵심
v9: 각 검증자는 원문을 독립적으로 해석하고, 모든 선택지의 정오/유일성 및 다른 방법·반례를 전부 확인한다.
정답을 가렸거나 별도 프로세스에서 계산했다는 사실만으로 독립 의미검증 완료라 하지 않는다.
v7.2: 일반 자동출제/문항은행은 필요한 객관적 검증을 충족하면 전건 인간승인 없이 자동적격 경로를 유지한다.
필수 인간승인은 교사고객 출제보조의 고객 최종 채택·배포에 한정한다. 확인결함을 사람승인으로 우회하지 않는다.
예측/목표/실측은 분리하며 근거 없는 난도·오답률 수치를 만들어 채우지 않는다.

4. Gemini 첫 지시문 예시
첨부자료의 역할과 현행 v9·v7.2 정책을 확인하라. 파일명, 읽은 범위와 레코드 수, 누락된 그림/자료를 먼저 보고하라.
선택한 역할 하나만 수행하고 출제·검증·관리자 역할을 합치지 마라. 원본을 임의 변경하지 마라.
실제로 호출하거나 실행하지 않은 작업을 완료로 보고하지 마라. API 실행영수증/모델ID를 만들어 내지 마라.
역할이 맞지 않는 자료를 함께 받았으면 오염된 검증을 계속하지 말고 새 분리 문맥이 필요함을 표시하라.

5. 이번 작업이 한 것 / 하지 않은 것
수행: Library 자료 탐색, 원본 수신, ZIP CRC 검사, 원문 TXT 추출, 역할분리, 레코드·이미지 해시·파이썬 구문 검사, 파일별 SHA256 기록.
미수행: Gemini 계정에 직접 첨부, 실제 GPT/Gemini API 호출, 3-Solver 의미검증, 유료 실행, 운영서버 배포, 특허 제출/변경.
이 묶음은 전체 Library/모든 채팅의 완전백업이 아니라 확인한 핵심 Gemini 이식자료의 선별본이다.
원본 ZIP/문항/코드는 Library에서 변경하거나 삭제하지 않았다. 전달 형식은 TXT와 원본 PNG이며 ZIP은 제공하지 않는다.

7. 파일 무결성
10_TRANSFER_MANIFEST_SHA256.txt의 파일별 SHA256과 원본/추출구간 정보를 확인한다.
02/03 파일은 이름만 변경한 원본 바이트 동일 사본이다. 나머지 TXT는 새 안내와 원문구간을 묶은 전달본이다.
구간별 원문 내용은 SOURCE_BYTES와 SOURCE_SHA256으로 확인한다. 내용을 줄여 요약하거나 잘라내지 않았다.
원본 SQLite는 직접 첨부하지 않고 동일 패키지의 기존 JSONL을 전달한다. SQLite 전체 테이블을 복제했다는 뜻은 아니다.
