에듀리커버AI 교사-Gemini 연동 문항생성 구조 정리
작성일: 2026-09-16
문서 성격: 내부 설계 정리안

중요한 버전 표기
1. 현재 확인된 “v10.2”는 교사용 에듀리커버 서비스의 정식 배포 버전명이 아니다.
2. v10.2는 “영어·수학 독립검증 직접읽기” 자료 묶음의 버전이다.
3. 따라서 이 문서는 “에듀리커버AI 교사 출제보조 + v10.2 검증 규격 연동안”을 정리한 것이다.
4. 교사 화면, Gemini API, 자동 배포까지 모두 완성된 상용 제품이라고 표시하면 안 된다.

======================================================================
1. 한 줄 정의
======================================================================

교사가 학년·과목·단원·출제 범위·난이도·문항 유형을 입력하면,
에듀리커버 내부 서버가 비공개 출제원리DB를 이용해 문제 초안을 만들고,
정답과 내부 출제기술을 제거한 문제지만 Gemini에 보내 독립 검토를 받은 뒤,
검증을 통과한 문항만 교사가 최종 채택하여 시험지로 만드는 구조이다.

Gemini의 역할은 “외부 독립 검토자”이다.
Gemini가 에듀리커버의 내부 출제원리DB, 정답DB, 생성 소스코드, 다른 검토자의 답을
읽거나 학습하는 구조가 아니다.

======================================================================
2. 가장 중요한 구분
======================================================================

[A] 실전 문제 제작
- 내신 시험, 수능형 모의고사, 학원 시험에 실제로 사용할 문제를 만든다.
- 시험지에는 발문, 지문·자료, 선택지 또는 답란만 들어간다.
- 산파식 질문을 문제 본문에 섞지 않는다.

[B] 해설·오답 복습
- 학생이 문제를 푼 뒤에만 제공한다.
- 필요하면 다음 두 종류의 “근거 확인 질문”을 붙일 수 있다.
  ① 학생이 핵심 근거를 스스로 찾게 하는 질문
  ② 가장 매력적인 오답과 정답을 구별하게 하는 질문
- 이것은 실전 시험 문항이 아니라, 제출 후 해설·복습용 질문이다.
- 이것을 무조건 “산파식 질문”이라고 부르지 않는다.

[C] 산파식 진단 수업
- 학생의 실제 답, 이유, 확신도, 풀이 흔적을 받은 뒤 오개념 원인을 구별할 때 사용한다.
- 교사가 “진단 수업 모드”를 켠 경우에만 작동한다.
- 문항 제작 단계나 실전 시험지 출력 단계에는 넣지 않는다.

======================================================================
3. 교사가 처음 입력하는 내용
======================================================================

필수 입력
- 학교급·학년
- 과목
- 단원 또는 시험 범위
- 성취기준·학습목표
- 출제 목적: 내신 / 수능형 / 모의고사 / 단원평가 / 보충평가
- 문항 유형: 객관식 / 단답형 / 서술형 / 순서 / 삽입 / 빈칸 / 내용일치 등
- 문항 수
- 난이도 분포
- 참고자료 또는 교사가 직접 입력한 원문
- 출력 형식

선택 입력
- 특정 출제원리 또는 사고 기능
- 피하고 싶은 유형
- 반드시 포함할 자료·표·그림
- 예상 풀이 시간
- 배점
- 해설 공개 여부
- 제출 후 “근거 확인 질문 2개” 제공 여부

참고자료를 넣을 때 기록할 항목
- 자료명
- 출처
- 버전·발행일
- 사용 권한
- 원문 파일 해시

======================================================================
4. 전체 처리 흐름
======================================================================

1단계. 교사 작업 생성
- 교사가 입력한 조건을 하나의 workflow_id로 묶는다.
- 고객 교사 customer_id와 작업 revision_hash를 만든다.
- 이후 수정할 때마다 새 revision_hash를 발급한다.

2단계. 출제 범위 고정
- 교사가 지정한 원문, 단원, 성취기준, 자료를 고정한다.
- 누락된 지문, 표, 그림, 밑줄 범위가 있으면 출제를 시작하지 않고 HOLD한다.
- 원문에 없는 내용을 임의로 보충하지 않는다.

3단계. 내부 출제원리 조회
- 에듀리커버 내부 서버만 비공개 출제원리DB를 조회한다.
- 학년, 과목, 단원, 발문 유형, 정답 근거 범위, 오답 논리, 난이도 조건을 조합한다.
- 특정 기출문제의 단어와 숫자만 바꾸는 방식은 사용하지 않는다.
- 여러 자료에서 추상화한 출제원리를 이용해 새로운 문항을 만든다.

4단계. 문제 초안 생성
- 문제 본문
- 지문·자료
- 선택지 A~E 또는 답란
- 내부 정답
- 정답 근거
- 각 오답이 틀린 이유
- 사용한 출제원리 ID와 revision
- 출처·권리 정보
를 서로 연결해 저장한다.

5단계. 기계적 구조 검사
- 문항 ID 누락 여부
- 중복 문항 여부
- 객관식 A~E 전체 존재 여부
- 빈 선택지 여부
- 지문·표·그림·밑줄 누락 여부
- 발문과 선택지 형식 일치 여부
- 파일 해시와 revision 일치 여부
- 정답이 선택지 안에 존재하는지
- 같은 선택지가 반복되었는지
를 검사한다.

이 검사는 문항의 의미가 맞다는 증명이 아니다.
형식 검사 프로그램 세 개가 모두 통과해도 “세 AI 독립검증 완료”라고 표시하면 안 된다.

6단계. Gemini용 블라인드 문제지 생성
Gemini에는 다음 정보만 보낸다.
- item_id
- 문제의 완전한 원문
- 필요한 지문·표·그림
- 발문
- 선택지 A~E 또는 단답형 답란
- 검토 결과를 돌려받기 위한 공통 출력 형식

Gemini에 보내면 안 되는 정보
- 제작자가 정한 정답
- 제작자의 해설과 풀이
- 오답 설계 코드
- 출제원리DB 원문
- 생성 프롬프트 전문
- 출제 소스코드
- 학생 개인정보와 응답 기록
- 다른 검토자의 답
- 이전 검산 결과
- 내부 관리자 메모

7단계. Gemini 독립 검토
Gemini는 문제를 처음 보는 검토자로서 다음을 수행한다.
- 원문의 조건과 범위를 직접 해석한다.
- 부정어, 수량어, 예외, 밑줄 범위, 지시 대상, 자료 조건을 확인한다.
- 문제를 독립적으로 푼다.
- 정답이 하나인지 확인한다.
- A~E 각 선택지가 왜 맞거나 틀리는지 확인한다.
- 다른 풀이, 반례, 경계값 또는 원문 직접 대조로 한 번 더 검사한다.
- 결정적 근거를 짧게 인용한다.
- PASS_CANDIDATE / HOLD / DEFECT 중 하나로 반환한다.

주의
- 한 채팅에서 Gemini가 S1, S2, S3 역할극을 한 것은 독립검증 3회가 아니다.
- 같은 정답을 내는 파서나 규칙 프로그램 세 개도 독립 AI 세 개가 아니다.
- 실제로 세 번의 독립검증을 주장하려면 세 개의 분리된 새 문맥에서 실제 요청과 실제 응답이 있어야 한다.
- 모델 이름을 세 개 붙였다는 이유만으로 독립성이 증명되는 것도 아니다.
- API 호출이나 실제 대화 기록이 없으면 “검증 실행 완료”라고 쓰면 안 된다.

8단계. 검토 결과 대조
다음 조건을 모두 만족할 때만 “내용 통과 후보”가 된다.
- 문제 revision과 검토 대상 source_hash가 일치한다.
- 검토자가 문제 전체를 읽었다.
- 정답이 하나로 확정된다.
- 모든 선택지 검토가 있다.
- 결정적 근거가 실제 지문 안에 존재한다.
- 대체 검산이 완료되었다.
- 누락 자료와 미해결 조건이 없다.
- 확인된 결함이 없다.

다음 경우에는 자동 채택하지 않고 HOLD한다.
- 정답 불일치
- 복수정답 가능성
- 정답 없음
- 지문 근거 부족
- 누락된 그림·표·밑줄
- 발문이 요구하는 대상이 불명확함
- 문법 문제의 밑줄 대상 누락
- 내용일치 문제에 불일치 선지가 여러 개 있음
- 정답과 해설의 근거가 서로 다름
- 오래된 revision에 대한 검토 결과

확인된 결함이 하나라도 있으면 다수결로 덮지 않는다.
문항을 수정하여 새 revision을 만들고 처음부터 다시 검증한다.

9단계. 교사 최종 검토
교사 화면에는 다음을 보여준다.
- 문제 미리보기
- 내부 정답과 근거
- 각 선택지 판정
- Gemini 검토 결과
- HOLD 또는 DEFECT 사유
- 이전 revision과 현재 revision의 차이
- 채택 / 수정 / 폐기 버튼

초안 생성과 내부 검증에는 매번 교사 승인을 요구하지 않는다.
다만 교사 고객의 시험으로 최종 채택하거나 배포할 때는 교사가 승인해야 한다.

승인은 다음 네 항목에 묶는다.
- customer_id
- workflow_id
- revision_hash
- action: FINAL_ADOPT 또는 PUBLISH_CUSTOMER_EXAM

교사 승인은 확인된 오류를 무효로 만드는 권한이 아니다.
확인된 결함, 필수 근거 누락, 오래된 revision, 잘못된 권한은 승인으로 우회할 수 없다.

10단계. 시험지 출력·배포
- 최종 승인된 revision만 시험지로 출력한다.
- 시험지에는 내부 출제원리, 정답, 검증 로그를 넣지 않는다.
- 교사용 정답지와 학생용 시험지를 분리한다.
- 배포 후 오류가 확인되면 해당 revision의 향후 노출을 즉시 중지한다.

5. 실전 문항 품질 기준
======================================================================

공통 기준
- 발문이 한 가지 과업만 요구해야 한다.
- 정답은 원문 또는 제시 자료에서 입증되어야 한다.
- 객관식은 의도한 정답이 하나여야 한다.
- 오답 네 개는 각각 실제로 틀리면서도 수험생이 고민할 만해야 한다.
- 원문에 없는 가정을 넣어야만 풀리는 문제는 사용하지 않는다.
- 선택지 길이, 극단어, 문체 차이만으로 정답이 드러나면 안 된다.
- 실제 반응자료가 없으면 오답률, 정답률, 변별도를 임의로 표시하지 않는다.
- “수능급”, “평가원급”, “고난도”는 실제 비교·파일럿 근거 없이 확정 표현으로 쓰지 않는다.

영어 독해 추가 기준
- 목적, 주제, 요지, 제목, 함의, 지칭, 내용일치 유형을 서로 바꾸어 판정하지 않는다.
- 부정 발문은 ‘거짓인 선지’가 정답이 될 수 있음을 반영한다.
- 지문에 없다는 이유와 지문과 반대라는 이유를 구별한다.
- 매력적인 오답은 정답 문장의 일부를 복사하는 방식이 아니라,
  범위 확대, 인과 뒤집기, 주체·대상 교체, 조건 누락, 세부 소재의 주제화처럼
  실제 독해 오류를 이용해 만든다.
- 같은 템플릿, 같은 극단어, 같은 무관문장 소재를 반복하지 않는다.
- 순서·삽입 문제는 단순 시간 순서만으로 끝나지 않게 지시어, 연결어, 정보 구조를 함께 사용한다.
- 문법 문제는 실제 밑줄 위치가 보여야 하며, 복수의 설명이 동시에 틀리지 않아야 한다.
- 도표 문제는 불일치 선지가 하나인지 계산으로 확인한다.

수학 추가 기준
- 정의역, 단위, 부등호 경계, 예외, 도형 조건을 모두 보존한다.
- 계산 결과뿐 아니라 자연어 조건을 식으로 옮긴 과정이 맞는지 확인한다.
- 근, 해집합, 요구값의 유일성을 구별한다.
- 필요한 공식이나 그림이 없으면 추측하지 않고 HOLD한다.

6. 교사 화면의 최소 구성
======================================================================

화면 1. 출제 조건 입력
- 학년 / 과목 / 단원 / 범위 / 유형 / 문항 수 / 난이도 / 자료 업로드

화면 2. 생성 진행 상태
- 초안 생성 중
- 구조 검사 중
- Gemini 블라인드 검토 중
- 통과 후보
- 보류
- 결함 발견

화면 3. 문항 검토
- 문제
- 정답과 근거
- 오답별 판정
- 검토 결과
- revision 비교

화면 4. 최종 처리
- 채택
- 수정 후 재검증
- 폐기
- 시험지 출력
- 학생용/교사용 파일 분리

======================================================================
7. 상태값
======================================================================

DRAFT
  초안 생성 상태

STRUCTURE_HOLD
  형식, 자료, 선택지, 해시 등에 문제가 있는 상태

BLIND_REVIEW_PENDING
  Gemini에 정답 없는 문제지를 보내고 실제 검토 결과를 기다리는 상태

PASS_CANDIDATE
  검토자가 내용상 통과 후보로 판정한 상태

HOLD
  근거 부족, 정답 불일치, 누락 자료 등으로 판단을 보류한 상태

DEFECT
  복수정답, 정답 없음, 발문 오류 등 확인된 결함이 있는 상태

CONTENT_EVIDENCE_PASS
  근거와 선택지 검토까지 완료된 내용 통과 상태

TEACHER_APPROVAL_PENDING
  교사 고객의 최종 채택 또는 배포 승인을 기다리는 상태

ADOPTED
  교사가 해당 revision을 최종 채택한 상태

PUBLISHED
  권한 확인 후 시험지로 배포된 상태

8. 예시: 교사 요청값

고객 교사: teacher-A
학년: 고등학교 2학년
과목: 영어
범위: 교과서 3과 본문과 추가 읽기자료
목적: 중간고사 대비 실전문제
유형: 제목 2, 빈칸 2, 순서 1, 삽입 1, 어법 2, 내용일치 2
문항 수: 10
난이도: 중 4, 중상 4, 상 2
출력: 학생용 시험지 + 교사용 정답·근거표
조건: 동일 지문 반복 금지, 동일 오답 템플릿 반복 금지
해설 후 근거 확인 질문: 사용
산파식 진단 수업: 사용 안 함

이 요청으로 생성된 문제지는 실전문제 형식만 유지한다.
근거 확인 질문은 시험지 본문이 아니라 제출 후 해설 화면에만 붙인다.

9. 현재 확인된 구현 상태
======================================================================

[확인됨]
- 영어·수학 독립검증 직접읽기 v10.2 자료가 존재한다.
- 문제지만 분리하여 정답과 이전 검산 결과를 주지 않는 규칙이 있다.
- 문항 분할, ID, source_hash, 누락·중복·선택지 형식 검사 규격이 있다.
- 검토 결과 반환 형식과 PASS_CANDIDATE / HOLD / DEFECT 구분이 있다.
- 교사 고객 출제보조에서는 FINAL_ADOPT와 PUBLISH_CUSTOMER_EXAM에 교사 승인을 요구하는 v7.2 참조 정책이 있다.
- 내부 출제원리DB와 자체제작 문제은행 설계 자료가 존재한다.

[일부 확인 또는 설계 단계]
- 내부 출제원리DB를 이용한 자동 문항생성
- 출제 조건과 문항 revision의 연결
- 독립검증 결과의 자동 대조
- 교사 최종 채택 흐름

[아직 실제 완성·배포가 확인되지 않음]
- 교사 로그인 화면에서 Gemini API를 직접 호출하는 상용 기능
- 세 개의 실제 독립 AI 요청을 자동 실행하는 운영 서버
- 교사용 통합 대시보드 전체
- 학교·학원 계정 및 결제 시스템
- 시험지 자동 배포 운영
- 새 문항의 실제 학생 정답률·오답률·변별도 데이터

따라서 현재 상태를 “교사들이 Gemini와 연동해 바로 문제를 만드는 v10.2 상용 프로그램 완성”이라고 표현하면 안 된다.
정확한 표현은 “기존 에듀리커버 출제·검증 자산과 v10.2 검증 규격을 연결한 교사 출제보조 설계안”이다.

10. 최소 개발 순서
======================================================================

1차. 내부 관리자용 파일럿
- 교사 입력 폼
- 문항 생성
- 문제지/정답지 분리
- Gemini 1개 실제 블라인드 검토
- 로그와 해시 저장

2차. 검증 강화
- 실제 분리 문맥 검토 추가
- 각 선택지 근거 검사
- 누락 자료 자동 차단
- 수정 revision 재검증

3차. 교사 대시보드
- 미리보기
- 수정
- 재검증
- 채택·폐기
- 학생용/교사용 출력

4차. 제한 파일럿
- 교사 2~5명
- 비밀유지 조건
- 실제 교사 시간 절감 측정
- 오류율, 보류율, 수정 횟수 측정

5차. 상용화 판단
- 검증 실패율과 비용 확인
- 개인정보·저작권·권한 점검
- 학교·학원 배포 기능 연결

11. 절대 금지사항
======================================================================

- Gemini에 내부 정답과 출제원리DB를 함께 보내기
- 한 채팅의 역할극을 세 AI 독립검증이라고 표시하기
- 규칙 프로그램 세 개의 일치를 세 AI 검증이라고 표시하기
- 실제 호출 기록 없이 API 검증 완료라고 표시하기
- 다수결로 확인된 결함을 무시하기
- 교사 승인으로 복수정답이나 근거 누락을 통과시키기
- 원문에 없는 자료를 AI가 추측해 보충하기
- 실제 학생자료 없이 정답률·변별도·오답 매력도를 확정하기
- 실전 시험지에 산파식 진단 질문을 자동 삽입하기
- 특정 기출 한 문제의 표현과 구조를 그대로 복제하기

13. 최종 정리
======================================================================

교사는 에듀리커버 화면에서 출제 조건을 입력하고 최종 문항을 채택한다.
에듀리커버 서버는 비공개 출제원리DB를 이용해 초안을 만들고 구조를 검사한다.
Gemini는 정답과 내부 기술을 보지 않은 상태에서 문제지만 독립 검토한다.
검토 결과가 맞더라도 프로그램은 자동으로 상용 배포하지 않으며,
교사 고객의 최종 채택·배포 승인과 revision 결속을 거친다.

실전 시험 문제, 제출 후 근거 확인 질문, 산파식 진단 수업은 서로 다른 기능으로 분리한다.
이 구분이 에듀리커버 교사 출제보조 구조의 핵심이다.
