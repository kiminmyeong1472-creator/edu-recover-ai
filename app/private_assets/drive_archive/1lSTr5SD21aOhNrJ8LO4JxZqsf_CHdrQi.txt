채팅·생활기록 무손실보존 및 임의삭제금지 고정원칙 v1.0
시행일: 2026-09-20
적용대상: 채팅 백업, 프로젝트 인계, 생활기록앱, 학생 학습기록, 첨부파일, AI 요약·분류·검색 인덱스

1. 최상위 원칙
원문은 기준자료이고 요약은 파생자료다. 요약·분류·중복제거·모델 컨텍스트 압축을 이유로 원문을 삭제하거나 덮어쓰지 않는다.

2. 3계층 저장
- RAW: 사용자·AI 메시지, 첨부, 도구결과, 수정본을 수신 순서대로 불변 저장한다.
- DERIVED: 요약, 주제분류, 결정사항, 작업상태, 오류목록, 검색색인을 별도 저장한다.
- LINK: 모든 파생기록을 source_message_id, attachment_id, revision_id, timestamp에 연결한다.

3. 임의삭제 금지
- 유사문장, 중복문장, 오래된 지시, 철회된 결정도 물리 삭제하지 않는다.
- 정정 시 이전 기록을 `SUPERSEDED`로 표시하고 새 revision을 추가한다.
- 중복은 `DUPLICATE_OF` 링크로 묶되 양쪽 원문을 보존한다.
- 요약은 원문 백업으로 간주하지 않는다.

4. 허용되는 삭제 예외
사용자의 명시적 삭제 요청, 법적 보존·삭제 의무, 개인정보 침해 또는 보안사고 대응에 한한다. 삭제 전 대상, 범위, 근거, 승인자, 시각, 복구가능성, 파생자료 영향범위를 기록한다. 가능하면 물리 삭제 전 접근차단·격리·비식별화를 우선한다.

5. 완전성 검사
- source_message_count = raw_record_count인지 검사한다.
- 모든 첨부에 파일명, MIME, 크기, 해시, 수신시각, 접근상태를 기록한다.
- 요약의 각 항목은 하나 이상의 원문 ID를 가져야 한다.
- 원문과 연결되지 않은 고아 요약, 첨부 누락, 범위 공백을 자동 탐지한다.
- 접근 실패는 `UNREADABLE`로 기록하고 내용을 추정하지 않는다.

6. 결정·지시 보존
지시, 정정, 금지, 예외, 완료, 미완료, 보류, 오류, 파일상태를 서로 다른 필드로 기록한다. 최신 결정만 보여줄 수는 있지만 이전 결정과 변경 이유는 이력에서 보존한다.

7. 생활기록앱 특별원칙
- 글, 사진, 음성, 영상, 위치, 건강·감정 메모, AI 요약을 별도 객체로 저장한다.
- AI가 같은 사건이라고 판단해도 자동 병합·삭제하지 않고 사용자에게 병합 후보만 제시한다.
- AI 요약 수정이 원문을 변경하지 않도록 한다.
- 삭제·정정은 tombstone과 revision history로 추적한다.
- 내보내기에는 원문, 파생요약, 변경이력, 첨부 manifest를 포함한다.

8. 컨텍스트 한계 대응
모델 대화창에서 오래된 메시지가 보이지 않게 되는 것은 백업이 아니다. 수신 시점에 RAW 계층에 기록하고, 새 창은 원문 인덱스와 최신 파생요약을 함께 조회한다. 접근하지 못한 과거 메시지는 복원했다고 주장하지 않는다.

9. 백업·복구
- 원문 저장 성공 뒤에만 백업 완료로 표시한다.
- 백업본마다 범위, 마지막 메시지 ID, 파일 해시, 생성시각을 기록한다.
- 새 백업은 기존 파일을 조용히 덮어쓰지 않고 revision으로 저장한다.
- 정기적으로 임의 표본 복원시험과 전체 건수 대조를 수행한다.

10. 금지행위
- 요약본만 남기고 원문 삭제
- 모델이 중요하지 않다고 판단한 내용 자동 삭제
- 상충하는 지시 중 하나를 흔적 없이 제거
- 첨부파일명만 저장하고 실제 바이트·접근상태 누락
- 실패한 백업을 성공으로 표시
- 현재 접근 불가능한 대화를 추정하여 원문처럼 기록

11. 적용 확인 체크리스트
[ ] RAW/DERIVED/LINK가 분리되어 있는가
[ ] 원문 건수와 수신 건수가 일치하는가
[ ] 모든 요약 항목에 source ID가 있는가
[ ] 수정·폐기된 결정도 revision에 남아 있는가
[ ] 첨부 manifest와 해시가 있는가
[ ] 삭제 예외가 감사기록에 남아 있는가
[ ] 생활기록 내보내기에서 원문과 변경이력을 함께 복원할 수 있는가

12. 버전이력
- v1.0: 원문 불변보존, 파생요약 분리, 임의삭제 금지, 삭제예외 감사, 생활기록 특별원칙을 고정했다.
