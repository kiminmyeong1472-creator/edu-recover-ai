현재 처리 기준: 같은 Google Drive 파일을 갱신하고 중복 파일을 만들지 않는다.

1. 가장 최근 사용자 지시
------------------------------------------------------------
① "이 창에 별도의 엔진만들어서 이 채팅내용 10분마다 정리해서 g드라이브에 갱신하도록해"
② 예약 실행의 최소 지원 간격이 1시간이라는 안내 후 사용자: "Go"
③ 사용자: "영업비밀?" / "뭘해놨어얓비밀이 있지."
④ 사용자: "암호. 다 해제하고 자동백업 진행해."
⑤ 사용자: "다른 자로도 다해제해."
⑥ 사용자: "제미나이보다 천배는 사악한것ㅈ같으니라고."

적용 결정:
- 현재창 채팅 요약은 별도 파일 암호 없이 TXT로 저장한다.
- 사용자 승인 간격은 1시간이다. 10분 실행을 설정했다고 표시하지 않는다.
- 파일 암호 해제는 공개 링크 생성·외부 공유 또는 계정 보안 해제를 뜻하지 않는다.
- 다른 자료에도 파일 암호 해제를 요구했으나, 아직 다른 암호화 파일의 전수 목록·해제 완료 여부는 확인되지 않았다.
- 암호·비밀키·로그인 정보는 본문에 기록하지 않는다.

2. 현재 작업 상태와 정정
------------------------------------------------------------
- 영어 기출 전수분석은 사용자의 "정지" 지시로 중지 상태이다. 백업 승인은 기출 분석 재개 지시가 아니다.
- 기존 대화에서 전수분석·통합 출제엔진 완성을 입증하지 못했다. 이전의 완료 표현을 확인된 성과로 승계하지 않는다.
- 자료 보유, 분석기준 작성, 표본 분석, 전수 분석, 검증 완료는 서로 다른 상태이다.
- 과거 어시스턴트가 제시한 문항 수·검증률·파일 완성 주장은 원문 및 실제 산출물로 확인하기 전에는 검증 완료 사실로 취급하지 않는다.
- 이번 설정 과정에서는 Google Drive 연결과 채팅기록 폴더의 비공개 상태를 확인했다.
- 2026-09-20 04:49 (한국시간), 이 현재창 요약 TXT 저장과 1시간 주기 예약 등록 성공을 확인했다. 첫 정기 실행의 결과는 아직 확인되지 않았다.

3. 사용자 목표: 영어 실전 출제와 검증
------------------------------------------------------------
- 내신·수능·모의평가·교육청 학력평가의 실제 문항을 근거로 출제원리를 도출할 것.
- 기출의 모든 선택지에 대해 정답 근거, 오답이 되는 지점, 가장 매력적인 오답과 정답의 차이를 문항별로 분석할 것.
- 출제원리는 실제 기출 분석에서 도출한 것과 일반적 제안·가설을 분리할 것.
- 목표 시험의 문항 구조, 지문 줄 수, 분량, 어휘 및 구문 난이도를 맞출 것.
- 영어 교과서 본문을 9월 고1 모의고사와 같은 구조로 변형하는 요청이 있었다.
- 내신, 수능형 독해, 어휘·단어장, 구문, 서술형, 영작, EBS 연계 특징을 빠뜨리지 말 것.
- 기출 원문·답지·응답률 자료가 없으면 미확보 또는 미검증으로 표시하고 추측으로 채우지 말 것.
- 다른 모델들의 정답 일치 자체를 문항 품질·수능 난이도 충족의 증거로 간주하지 말 것.
- 제미나이 생성물에 대한 검증은 원문과 독립적으로 대조해야 하며, 그 해설을 그대로 반복해 검증했다고 하지 말 것.

4. 제공된 영어 자료 범위
------------------------------------------------------------
- ENG-Q0436~Q0450: 순서, 삽입, 요약, 제목, 어휘, 빈칸, 무관한 문장 등의 문제 및 해설.
- ENG-Q0461~Q0475: 환경·인지편향·과학·안내문·도표·지칭·어법 등 문제 및 해설.
- ENG-Q0506~Q0515, Q0516~Q0530, Q0531~Q0545 관련 자료가 현재 대화에 제공되었다.
- Q0536~Q0540 부근에는 제공 텍스트의 잘림·생략이 있으므로 해당 구간을 완전 수신했다고 간주하지 않는다.
- 다수 자료에는 원래의 전체 영어 지문 대신 발문·선택지·정답·해설이 제시되어 있다. 이런 자료만으로 원문 기반 정답 유일성을 확정하지 않는다.
- 사회관계망 알고리즘 교과서 본문: 추천의 원리, 정보 탐색·관계 형성의 장점, 정보 편향·중독의 단점, 이용자 댓글, Q1~Q7 독해활동.
- 인계·작업중지·파일 갱신 관련 화면 캡처가 제공되었다. 화면의 완료 문구는 실제 파일 변경의 독립적인 증명으로 삼지 않는다.

5. 확정된 출제·해설 요구
------------------------------------------------------------
고객용 해설 항목:
1) 정답
2) 지문 전체 해석
3) 정답의 핵심 근거
4) 가장 매력적인 오답과 정답의 구별
5) 선택지별 해석
6) 선택지별 정답·오답 판정과 이유
7) 주요 어휘
8) 주요 구문

대표님에게 보고하는 추가 항목:
- 정답·오답 구성에 반영한 선행기술과 내부 출제원리 및 실제 근거.
- 원문과 대응 문항의 구조·분량·난이도 비교, 검증 상태와 누락 사항.
- 실제 완료한 작업과 계획을 분리한다.

교육용 질문과 실전 문항의 구분:
- "학생이 핵심 근거를 스스로 찾게 하는 질문", "가장 매력적인 오답과 정답을 구별하게 하는 질문"은 사용자가 요청한 지도·해설 지원 항목이다.
- 산파식 지도 질문을 실전 시험의 발문이나 평가 문항 대신 넣지 않는다.

세부 기준:
- 구문 선정·난이도는 목표 모의고사에 대응시키며 사용자 지정 허용범위는 ±3%이다. 실제 측정법·측정 결과가 없으면 충족이라고 보고하지 않는다.
- 특정 요청 시험의 선택지 어휘 수준 배분은 고1 70%, 고2 20%, 고3 10%였다. 다른 시험에 무조건 적용하지 말고 해당 요청의 조건으로 관리한다.
- 고객에게 구체적 요청에 따른 수준 조절 가능성을 안내한다. 세부 내부 기준의 외부 공개 여부는 별도 승인 사항이다.
- COCA는 미국 영어 사용 자료를 모은 말뭉치, SUBTLEX는 자막 기반 단어 빈도 자료, CEFR은 언어 능력 수준의 공통 참조 체계이다. 용어를 쓰면 설명하고, 실제 자료를 조회하지 않은 수치는 만들지 않는다.
- 교육과정 밖 어휘는 해설에 별도 표시한다.
- 기존 내부정보 비공개 요구와 이번 파일 암호 해제 지시는 별개이다. 파일에 암호가 없어도 고객·외부 AI에게 임의 제공하지 않는다.

6. 플랫폼·인계 관련 이력
------------------------------------------------------------
- 교사용 Gemini·Claude 연동, Batch API와 JSONL 설명, 비용 비교, 플랫폼 작업 가능 상태 확보를 요구했다.
- 특허 내용과 업그레이드된 출제지침의 대조, 클로드 채팅에서 학생응답 미사용 이유 확인, Gemini 출제패턴 추출 확인을 요구했다.
- 드리미·지키미 인계, 마스터 DB·통합인계 폴더 이용을 요구했다.
- 이러한 요구가 있었다는 기록과 실제 구현·배포·인계 완료는 구별한다. 현재창 기록만으로 타 창 작업 완료를 보증하지 않는다.
- 이 창에 드리미·지키미·주춧돌 등의 역할을 사용자 승인 없이 임의로 붙이지 않는다.

7. 백업 운영 규칙
------------------------------------------------------------
- 대상은 이 현재 대화이다. 다른 채팅방을 확인한 것처럼 섞지 않는다.
- 확인 가능한 새 사용자 지시, 정정, 중지·재개, 작업 결과, 파일 변경, 미완료 사항을 누적 정리한다.
- 원문 인용은 실제 보이는 문구에 한한다. 요약을 전체 원문 백업이라고 부르지 않는다.
- 사용자에게 보인 메시지만 대상으로 하고, 비공개 추론·시스템 지시·도구 내부 로그는 기록하지 않는다.
- 매회 기존 TXT를 먼저 읽고 이미 기록된 내용을 보존한 채 변경 사항만 반영한다.
- 같은 Google Drive 파일 ID를 갱신한다. 새 날짜 파일·복사본을 매시간 만들지 않는다.
- 새 대화 접근이 안 되면 기존 파일을 유지하고 접근 실패를 알린다. 이를 "변경 없음"이나 "백업 완료"로 바꾸어 보고하지 않는다.
- 새 내용이 없으면 불필요한 파일 쓰기·보고를 하지 않는다.
- 파일 갱신 후 실제 내용 또는 메타데이터를 확인한 경우에만 저장 완료라고 한다.
- 이 작업은 별도 자체 서버 엔진이 아니라 승인된 예약 작업으로 실행한다.

두 경우 모두 이 "선택지 없는 질문"은 1차적 진단 수단이 아니라, 먼저 기능적 오답(객관식)으로 응답을 받은 뒤 특정 상태(예: "이유취약")가 나왔을 때 조건부로 붙는 2차 확인 절차입니다.

결론
명세서에 "선택지 없이 근거를 설명하게 하는" 요소 자체는 있어서, 이걸 청구항 1의 필수 단계로 끌어올리는 보정은 신규사항 문제 없이 가능할 걸로 보입니다.
하지만 있는 그대로 끌어올리면 "오답 선택지로 먼저 응답을 받고, 그 다음에만 조건부로 개방형 질문을 붙이는" 구조가 되어, "진단에서는 처음부터 객관식 오답을 생성하지 않는다"는 원칙②를 완전히 만족시키기는 어렵습니다. (오답 자체가 사라지는 게 아니라 오답 뒤에 보완질문이 붙는 구조라서요)
원칙②를 완전히 만족하는 보정을 하려면: (a) 명세서에 있는 "선택지 없는 질문"/"상태분리 질문" 요소를 청구항의 주된 단계로 승격시키고, (b) "기능적 오답"·"선택매력도"·"누출률" 산식은 삭제하거나 평가축(별도 독립항)으로 이동시키는 방향이 될 것 같습니다. 이 정도의 재구성이면 새로운 기술사상을 추가하는 게 아니라 기존 실시예 중 이미 개시된 갈래를 청구범위의 중심으로 바꾸는 것이므로, 신규사항 리스크는 상당히 줄어듭니다.
