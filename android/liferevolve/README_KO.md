# 생활의 혁명 LifeRevolve Android 0.3.0

공식 플랫폼을 여는 별도 Android 앱입니다. 앱 아이콘과 플랫폼 화면은 휴대폰을 보는 AI 캐릭터를 사용합니다. 앱을 실행하면 `https://edurecover-prod-production.up.railway.app/life`를 엽니다. 별도 앱 식별값은 `kr.edurecover.liferevolve`이며 과거 ScreenWitness 시험앱과 다릅니다.

## 실제 기능

- 공개된 Android 화면 공유 기능(MediaProjection)으로 사용자가 허용한 앱 또는 전체 화면을 취득합니다. 운영체제 허용 화면은 생략하지 않습니다.
- 새 프레임이 도착하면 화면 전체를 최소 2초 간격으로 PNG에 보관합니다. 정지 화면에서 운영체제가 새 영상을 주지 않으면 새 파일도 만들지 않습니다. 이미 받은 영상의 줄 끝 여백만 제거하며 실제 화소를 추가하거나 축소하지 않습니다.
- 보관함에서 화면을 확인하고 갤러리의 `Pictures/LifeRevolve`에 PNG 원본을 저장하거나 선택한 앱으로 공유합니다.
- 플랫폼 `/life/screen`의 사진 선택을 실행하면 ‘취득한 화면 보관함’ 또는 ‘갤러리·파일 앱’을 선택할 수 있습니다. 파일을 선택했다고 서버 저장까지 완료한 것은 아닙니다. 플랫폼에서 실제 저장 결과를 확인해야 합니다.
- 앱에 보관한 과거 화면을 현재 화면이라고 표시하지 않습니다. OCR(사진의 글자를 읽는 처리), AI 자동 호출, 실시간 결과 덧씌우기, 자동 긴 화면 합성, 문서 전체 확보율 측정은 이번 버전에서 실행하지 않습니다.
- 화면 크기가 바뀌면 같은 가상 화면(VirtualDisplay)을 조정합니다. 화면 공유 허용 한 번을 재사용하여 가상 화면을 두 개 만들지 않습니다.
- 보관함 전체 한도는 40장 또는 128MB이며, 화면 한 장이 8백만 화소를 넘으면 축소하는 대신 오류를 표시하고 중단합니다. 보관함의 화면을 삭제하면 그만큼 다시 취득할 수 있습니다. 갤러리로 저장한 사본은 앱 내 삭제로 지워지지 않습니다.

## 보안 경계

플랫폼에서 앱의 내부 Java 기능을 호출하는 원격 JavaScript bridge는 만들지 않았습니다. 앱 안에서는 빌드 시 지정한 동일 HTTPS origin만 엽니다. 사용자가 직접 선택한 외부 HTTPS 링크는 별도 브라우저로 엽니다. HTTP·파일 주소·스크립트 주소의 내부 탐색, 혼합 콘텐츠, 웹의 임의 내부파일 읽기는 허용하지 않습니다. 로그인은 기존 플랫폼 로그인 페이지와 쿠키를 사용하며 인증 우회나 API 키 내장은 없습니다.

PNG 공유용 ContentProvider는 외부 공개가 꺼져 있으며 선택한 URI 한 개에만 읽기 권한을 부여합니다. 파일 이름을 정규식과 실제 상위 경로로 검사합니다. 파일을 쓰거나 메타데이터 JSON을 읽는 외부 경로는 없습니다. 앱 삭제 시 앱 내부 보관 화면은 삭제됩니다.

## 실제 빌드

준비물은 Python 3와 Java 17 이상입니다. `javac` 명령이 없어도 Java의 `jdk.compiler` 모듈이 설치돼 있으면 사용할 수 있습니다.

```sh
python3 tools/setup_android_sdk.py
PLATFORM_ORIGIN=https://edurecover-prod-production.up.railway.app python3 tools/build_apk.py
```

설치 파일은 `LifeRevolve_0_3_0_20261022.apk`입니다. 캐릭터 이미지 원본은 `assets/companion.png.base64`의 글자 형태로 보존하고, 빌드 시 원본의 SHA-256(파일 내용 확인값)을 대조하여 PNG를 복원합니다. 이미지를 축소·편집하지 않습니다. 빌드 도구는 Google 공식 Android SDK 배포 목록에서 API35 platform과 build-tools35.0.0을 받고 목록의 체크섬을 대조합니다. 실제 운영 HTTPS 주소를 넣지 않으면 빌드를 중단합니다. 같은 코드·환경으로 다시 만들기 위한 도구이며 바이트 단위 재현 가능한 빌드를 주장하지 않습니다.

현재 APK는 시험용 서명을 사용합니다. `.signing/debug.keystore`는 소스 저장소에 넣지 않으며 후속 업데이트를 만들 때 같은 키를 안전하게 보관해야 합니다. 정식 배포 서명·앱스토어 제출은 완료하지 않았습니다.

## 자동 검사와 실기기 검사 구분

`tools/build_apk.py`는 Java 검사 26개, Android Java 전체 컴파일, Android 자원 연결, DEX 생성, APK 정렬, 실제 서명과 서명 검사를 실행합니다. 주소 우회, 파일 경로 탈출, 보관 한도, 화소 수 오버플로, 줄 끝 여백 제거, 마지막 영상 줄이 잘린 경우를 검사합니다.

아직 삼성 실기기에서 직접 시험하지 않았습니다. 다음 항목은 폰에서 확인해야 합니다.

1. Android 14·15·16에서 공유 허용/거부, 시작·종료·OS 강제종료와 재시작.
2. 삼성 폴더블의 접힘·펼침·가로세로 회전 중 PNG 크기와 내용.
3. 갤러리 문서·브라우저 긴 화면을 천천히 스크롤했을 때 실제 글자와 가장자리 보존 여부. 2초 사이의 미취득 내용은 복구했다고 주장하지 않습니다.
4. 보호된 화면·다른 앱 알림·가림·검은 화면의 실제 취득 형태.
5. 보관함 PNG 선택→플랫폼 로그인→사진 업로드·목록 재열기. 연결 코드 존재와 서버 저장 성공은 다릅니다.
6. 갤러리로 PNG를 저장한 뒤 실제 위치, 공유받은 앱의 파일 읽기, 앱 삭제 전 별도 보관 여부.
